 In LLM-based recommendation, effectively plays the role of a user-level agent, typically built on top of a memory-augmented backbone. Yet under this paradigm users and items remain asymmetric participants: only the user is given a structured profile; that profile is consumed inside a bandwidth-limited reranker prompt; and it is frozen after warmup. Starting from this observation, we recast LLM-based recommendation as an process in four stages: a self-description, it along the collaborative graph, the other side, and it from the next interaction. Analysing the dominant memory-augmented paradigm through this formulation, we identify three open communication challenges that current pipelines leave unaddressed: the item side never produces a comparable self-description ; profile-level signals are routed only into a bandwidth-limited reranker prompt rather than into the retrieval stage where they would not compete for context tokens ; and the user's description is frozen after warmup with no principled update rule . We instantiate the missing stages as } , a training-free, three-operator addition to a frozen LLM backbone: a rule-extracted symmetric item profile , a channel-decomposable profile-level homophily $ $ consumed at retrieval time rather than inside the reranker prompt, and a single-pass reflective update realising profile evolution without any gradient step. HARP integrates three training-free innovations: Dual Profile , Homophily Gate , and Reflection .} Large language models are becoming the central reasoning engine of next-generation recommender systems~. In the most representative paradigm~, a user is modelled as an LLM agent with persistent memory, and personalised recommendations are produced by routing collaborative-neighbour memories into a reranker prompt. Yet this paradigm provides only a partial answer: the user side is equipped with memory while the item side has no structured profile aligned with the user's; the user profile is consumed solely inside a bandwidth-limited reranker prompt; and the profile built at warmup is not revised from recommendation outcomes afterwards. We recast LLM-based recommendation as a four-stage agentic-communication process between user and item agents , and show that the dominant paradigm implements only a partial version of it, leaving three communication challenges open . The stages ------ borrow directly from heterogeneous message passing on graphs~ and from the classical study of homophily on social networks~. The decomposition plays a role: as an that asks which of the four stages a given pipeline implements and how well, and as a that prescribes the operator to add once a missing stage is identified. The four-stage view is thus an analytical framework for diagnosing a pipeline, not a model in itself. Recommender systems have passed through three architectural generations , yet the collaborative signal pervading all three is indexed by interaction rather than description-level compatibility, hence size-blind: whenever two agents' description sets differ sharply in breadth, raw interaction-overlap similarity inflates the match for reasons of degree rather than relevance, and the pre-rerank candidate list inherits that inflation. An agentic communication pipeline therefore needs a profile-level, coverage measure read from the query side's vantage, which is the role the channel-decomposable homophily $$ of plays once the item side is also allowed to speak.
