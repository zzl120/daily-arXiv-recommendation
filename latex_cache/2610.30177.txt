Visual document retrieval retrieves pages from their rendered appearance, preserving evidence in tables, figures, and layout that can be difficult to recover through text extraction. Multi-vector retrievers such as ColPali combine a vision--language encoder with token-level late interaction to capture fine-grained query--page correspondences. With document representations prepared offline, online retrieval still requires query encoding and vector-level matching against the stored representations . The resulting challenge is to reduce this computation while retaining the information needed for accurate retrieval. Compression and elastic representation learning make smaller representations available: Matryoshka embeddings support nested widths of the final-layer representation , while depth-aware extensions make intermediate-layer representations available for retrieval ) . Token pruning and pooling reduce the number of document vectors involved in matching . A deployment-fixed configuration, however, assigns the same depth, width, and token count to every query. Choosing such a configuration sets a common compromise between representation capacity and computation across the query workload. Adding more configurations broadens the available choices, but a fixed selection still leaves the incoming query without a role in deciding which representation to use. Learning useful compact representations and deciding when to use each one therefore remain distinct parts of the retrieval problem. This motivates our central question: Query-adaptive allocation poses two design requirements. Dynamic early-exit models provide a precedent by using intermediate predictions and adjustable inference-time thresholds to control encoder computation . The allocation choice must be made before executing the remaining encoder layers, using query information available at an early stage. Running every candidate route before choosing one would already incur the computation that allocation is intended to avoid. The decision must therefore anticipate the retrieval value of query representations that have not yet been produced. Changing the desired computation level should not require learning a new allocation rule. A query may be processed under different resource preferences, so its representation choice should remain adjustable after training. To address these requirements, we introduce , a framework for query-adaptive budget allocation within a single retriever ). Its Budget Allocator predicts the retrieval utility of candidate routes from early query features and combines these estimates with a resource preference to select a route. The utility estimates describe what each representation is expected to offer for the current query, while the resource preference determines how strongly selection favors compact configurations. Learning the utilities independently of this preference allows the same predictions to be reused when the desired quality--computation trade-off changes. The candidate routes jointly vary encoder depth, embedding width, and query/document token count, with learned compact representations and the native full route providing the available choices. The resulting retriever can adjust its computation without retraining or switching models. Our contributions are as follows: We develop a Budget Allocator that predicts route-specific retrieval utility from early query features and uses a separately specified resource preference to select a representation budget. We integrate selectable encoder depth, embedding width, and query/document token count into a common route family, with compact representations and the native full route as allocation choices.
