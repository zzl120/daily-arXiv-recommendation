We call the component that owns this loop the , and its rise has changed what a retrieval layer is for: once the harness can grep a corpus and read what it finds, the classical objectives of the retrieval layer---better chunking, better embeddings, higher Recall@$k$---stop being the binding constraint. This paper contains no vector index and no dense-retrieval leg, and the reason is empirical rather than aesthetic: adding a dense leg lowered accuracy in our runs, in the same direction as the reports of the teams cited below. It does not solve the of answering. An agentic loop is a search procedure with a language model inside it, and a procedure without discipline degenerates into blind exploration: it rewrites the same keywords, rereads the same document, piles dozens of marginal passages into the context, and finally bets on the model's patience for an answer. Every turn costs tokens, and every irrelevant passage competes with the relevant one for attention~. This paper argues that the layer missing from this picture is : a configurable pipeline that uses LLMs to enrich source documents with context that is not present in any chunk on its own---navigation trees whose leaves are atomic claims with verbatim evidence, entity relations, timelines, mind maps, ontology labels, synthesized articles, and durable memory. Compilation happens once, upstream of queries, and produces typed artifacts rather than a single index; retrieval then consumes those artifacts instead of raw text. Compilation is the supply side, the harness is the control side, and the tools are the interface between them . The marginal value has moved from finding to supplying, and the centrality of compilation does not depend on beating search at recall---it does not. An agentic loop can stop too early, answering from the first plausible passage, or never stop, accumulating evidence until the budget runs out. The second failure is more expensive: without discipline the loop rewrites the same query, rereads the same document, and fills the window with dozens of passages that are individually relevant and collectively useless. The process has consumed tokens, but it has not become an answer. The harness exists to make the loop converge. Its job is not to make the model smarter or to give it every tool, but to guarantee properties a language model cannot guarantee for itself: that compiled evidence is fetched before the first call, that insufficient evidence is discarded rather than accumulated, that tools which do not work on this corpus are not offered, and that an abnormal stop still produces an answer. The framework owns the invariants---prefetch, sufficiency judgment, discarding an insufficient block, removing tools proven useless on this corpus, degrading model calls under budget, assigning citation identifiers at delivery, and composing a fallback answer on abnormal termination---because a model cannot be trusted to enforce its own budget or number its own citations reliably. The model owns the judgments that need semantics over underspecified language: choosing query terms and reading order, judging whether a passage is relevant, and stating what evidence is still missing. Mixing the classes---asking the model to enforce a budget, or the engine to judge relevance---is the usual source of unreliable agents. Tool lists are usually organized by implementation: search, browse, read, grep, graph. We organize tools by the failure they remove, with one primary failure per tool, one observable symptom, and one metric; if two tools remove the same failure, one is a configuration of the other, and if a tool removes no named failure, it is a demo. The failures we cover are vocabulary mismatch , localization at scale , relations across sources , temporal ambiguity , synthesis burden , and tool or syntax error . RAGFlow implements a navigation tool and a graph explorer. The navigation tool supports several strategies: aggregate documents from search results and refine to chunks through each document's own navigation tree , or locate documents through claim and evidence search. In our benchmarks neither tool showed significant value. The weakest option we measured is the one now common in long-context RAG: let the harness read a navigation tree's table of contents and let the LLM choose which documents to read---very low accuracy at very high token cost---which surrenders the core value of a search harness, finding the answer quickly, accurately, and cheaply. Search will never die. Navigation tools are therefore optional in RAGFlow: on a corpus with no compiled artifacts the agent can use BM25 and grep alone, or also call the navigation tools, whose internals are a search-based aggregation; on a corpus with a compiled navigation tree they are not used at all, because claims and evidence projected onto the search results plus the sufficiency gate answer the same question at substantially lower token cost. A zero-hit result is a property of the tool, not a fact about the corpus, and a harness that lets the model read ``0 results'' as absence has transferred an engine failure into a semantic conclusion. The harness explains the zero before the model sees it and retries along the fallback ladder---relax the filter, switch from compiled to raw lexical search, widen the time window---before the model may conclude that the corpus is silent. This small protocol prevents the most common false negative in agentic retrieval, where the agent gives up because a tool was misconfigured rather than because the answer is missing. A zero-hit explanation is a control message, not evidence, and it never receives a citation number. The query passes through five stations, sequential by default and skippable only by explicit configuration. Before the model sees any tool, the harness asks whether this corpus has compiled artifacts at all: a corpus that was never compiled is not worth querying structurally, so navigation, graph exploration, and PageIndex outline tools are not exposed---not even their descriptions. Before the model decides how to search, the framework performs one evidence recall across the whole corpus, as direct claim search or as raw search with substitution; either way it is a flat read, not a document route, because routing through a tree is biased---a small tree sends every question to the same one or two documents. The harness checks sufficiency by count, source diversity, and coverage of the question; if the evidence suffices, one model call answers from it and the loop reads no raw text, and if it does not, the whole block is discarded rather than stuffed into the prompt. If the gate rejects the prefetch, the model enters the loop with the remaining tools; multiple retrieval actions in one turn execute in parallel, a step limit and a wall-clock budget make the loop converge by construction. If the loop ends abnormally, the framework composes an answer from the question and the evidence already in hand. The stations imply a small set of invariants. : compiled evidence is fetched before the first model call. : a rejected block is removed entirely, including from the system prompt and the citation table. : tools are exposed only if the corpus supports them and the tool has been useful there. : model calls are retried or degraded under a token and time budget. : identifiers are assigned when evidence is delivered, not generated by the model. : every query ends with an answer or an explicit failure. These invariants are unglamorous, and that is the point: they are the difference between a demo that sometimes works and a system that can be operated. The design is deliberately opposed to the ``let the model choose among many tools'' style. Tool choice is a decision the model makes poorly when the toolset is large and the corpus unfamiliar; it consumes turns and produces confident but unproductive plans. The harness instead decides which tools are admissible, and the model decides how to use the admissible ones. RAGFlow implements the design as a configurable ingestion pipeline feeding a stateful harness. The pipeline is a sequence of replaceable skills---parse, chunk, enrich, validate, assemble, register---and a template selects which artifacts are produced ; the other templates reuse the same skills and write different artifacts. Each compiled unit is stored with claim text, verbatim span, source chunk identifier and offsets, validity metadata, extractor version, and access labels; the store is versioned and content-addressed, so a claim resolves to the exact document version that produced it and can be highlighted in the source. The harness surfaces compiled units at the point of retrieval: claims are attached to the ordinary locate results, and a chunk-anchored lookup projects a recalled chunk to its claims. Navigation and graph tools are exposed only when the configuration calls for them: on a corpus with no compiled artifacts they are available as an optional aid, and on a corpus with a compiled navigation tree they are not used, because claims and evidence projected onto the search results answer the same question at lower token cost . Prefetched claims are grouped in document/page order and scored by a decision judge before admission. Of two decision models we evaluated---the Qwen decision model~ and the StartLux decision model~---the Qwen-based one was far more reliable and faster than StartLux , so it is the default. Both are small models released for exactly this role---deciding whether a block of evidence suffices---rather than general-purpose answering models. The harness therefore relies on row-level decision filtering and does not truncate pages by count alone ; when judge calls are slow or fail, it degrades gracefully. The compiler and the harness meet at a small set of serving paths rather than one abstract interface: an existence probe over , a chunk-anchored claim lookup, and a per-tool serving policy with three modes---off, compiled-only, and compiled-first with raw text on demand. The evidence gate is inserted where context can enter or leave the model---at prefetch admission, where the block is scored by unit count, source diversity, and entity coverage and either admitted with citations or discarded; at tool-result admission, where results are deduplicated, validated, and projected to units; and at delivery, where every claim must resolve to a delivered unit and a live source version. The harness never asks the supply side whether evidence is sufficient; that remains the gate's decision, which keeps the compiler replaceable and the gate testable without a compiler. A gate threshold cannot be tuned on the queries it rejects, because their counterfactual answer is unobserved. We therefore run the gate in shadow on a hash-bucketed share of production traffic: it computes and logs the decision but does not enforce it, and the query proceeds through the uncompiled path. A threshold is promoted to enforcement only when the accepted branch is non-inferior in accuracy and clears the token or latency target; otherwise the gate stays a logger. What an agent needs in order to answer well is high-quality context, and knowledge compilation is how that context is produced: claims with verbatim evidence, entity relations, timelines, ontology labels---typed, versioned, and governed. A system whose job is to produce and hand over that context, rather than to rank and return chunks, is an agent-native database. It is not a relational database: there is no query language and no schema enforcement, and the harness rather than the store decides what a given question reads. We report one compiler and one answering model, so the qualitative conclusion---evidence helps cost, structure does not help recall---is what we expect to generalize, not the exact percentages. The harness invariants are implemented in one system and validated by deployment, not by a controlled user study. The retrieval layer is being absorbed into the search harness, and with it the old objective of beating lexical search on recall. Under a competent harness, structural compilation does not do that: summary trees, PageIndex outlines, wikis, and graphs produced no detectable accuracy gain on FRAMES, and a PageIndex outline became a liability at scale. Claim--evidence pairs, installed as the leaves of a carrier tree, cut total query tokens by 91\ The broader claim is architectural: knowledge compilation is not one technique but a configurable ingestion pipeline that adds context upstream---claims for cost, trees for organization, graphs for relations, ontologies for governance, wikis for synthesis, timelines and mind maps for orientation, memory for continuity---while the harness decides what enters the window and the engine is the exact executor. Context becomes infrastructure when it is compiled once, typed, versioned, and governed, and when each artifact is judged on the ledger it was built for. The architectural implication is that the system is no longer only a RAG or retrieval engine. Once context is compiled upstream, an agent no longer queries a ranked list of chunks; it is supplied with high-quality, provenance-bearing context that is compiled once and reused across queries, artifacts, and sessions. That supply function is what we mean by an agent-native database: the compiled artifacts are the data, the harness decides what enters the window, and the tools are the only path from stored context to model. It is not a relational database and not a new retrieval paradigm; it is a different answer to the question of what a retrieval system owes the agent---not a ranked list of passages to read, but the smallest sufficient set of verified facts, supplied in advance and governed like data.
