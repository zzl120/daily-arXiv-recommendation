In Web content mining, it supports complex information seeking and fact verification across related pages~. Multi-hop questions make this evidence requirement more demanding because their answers depend on linked facts distributed across pages about related entities~. Answering these questions requires retrieving evidence units, such as documents, passages, or chunks, that jointly support the necessary reasoning steps. A collection of individually relevant units can still omit a fact needed to complete the reasoning chain. Multi-hop retrieval is fundamentally an evidence-set recovery problem, with the goal of recovering the complete supporting set within a given retrieval budget. By improving multi-hop question answering over interconnected Web content, our work aligns with the {figures/final/motivation.pdf} Recovering a complete supporting set requires more than matching individual evidence units to the original question. Single-round dense retrievers learn semantic matches between questions and candidate evidence~, but independent scoring can miss complementary units whose relevance becomes apparent only after intermediate facts are found. Iterative retrieval addresses this limitation by conditioning subsequent searches on retrieved passages or intermediate reasoning~. In these approaches, evidence dependencies are conveyed through retrieval history, leaving entity relations across documents implicit. Graph-based RAG makes these connections explicit through entities and relations~, while neural graph retrievers learn to integrate connected evidence through query-conditioned message passing~. A central question in learned graph retrieval is how accumulated relational context should guide subsequent evidence acquisition. Fixed-query designs update entity representations while retaining the original query condition~. As illustrated in Figure~, identifying the author of shifts the remaining information need toward that person's birthplace, while a fixed query can continue to favor book-related evidence. These designs accumulate relational context in entity representations without an explicit feedback path for that context to revise the query condition governing subsequent propagation. The query state should evolve with the evidence representations it guides. Intermediate entities and relations can clarify what remains to be retrieved, so accumulated graph context should inform both the representation of evidence and the condition used to explore further evidence. Coupling these updates brings relational propagation and query adaptation into the same retrieval process, allowing newly established context to guide the recovery of missing support. We introduce , a graph retrieval framework that couples recurrent query evolution with evidence propagation to support multi-hop question answering. It maintains a shared query state alongside entity representations that accumulate relational context through message passing. Between successive propagation layers, query-conditioned attention summarizes all entity representations, making context distributed across the graph available to the query update. A gated recurrent transition integrates this summary with the preceding query state to revise the retrieval condition. Boundary feedback injects the updated state at question-linked entities, while relation feedback modulates the features used to transform neighboring messages. These interfaces change both the context injected into the graph and how evidence propagates across its relations, closing the feedback path from accumulated evidence to subsequent retrieval. Finally, entity scores are aggregated into a document ranking that supplies evidence for answer generation. On four representative multi-hop QA datasets, QueryFlow achieves macro R@10, FR@10, and LLM-Acc gains of 4.98, 8.40, and 8.0 percentage points over representative baselines, respectively. Improvements in evidence coverage and complete recovery are accompanied by higher downstream QA reasoning accuracy, supporting the value of complete evidence retrieval for multi-hop question answering. Document associations redistribute each entity's score across its source documents. An entity appearing in one document contributes its full score there; one appearing in several documents divides that contribution equally among them. This property controls how graph relevance transfers to documents without selecting a fixed number of entities. Each document can still accumulate contributions from multiple entities, so its rank depends on their combined relevance and document frequencies. The weighting acts on entity frequency rather than normalizing by document length.
