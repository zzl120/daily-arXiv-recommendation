Generative recommendation has recently emerged as a promising paradigm for sequential recommendation~. Rather than retrieving items from an external index built over learned user and item embeddings~, generative recommendation decodes the identifier of the target item directly, representing each item as a sequence of discrete codes derived from its content embedding~. This places items and words in the same output space and has proven competitive with other strong sequential recommenders~. However, these models rely on a fixed interaction history to infer user preferences and generate recommended items, giving users no direct way to correct the system when its recommendation misses their current intent~. When the user's preference changes or the recommendation fails to capture what they currently want, the model cannot receive that correction explicitly. Instead, the updated preference must first be reflected in subsequent item interactions before it becomes observable to the model, making preference correction indirect and potentially slow. Conversational recommendation systems let users express preferences through dialogue~, but they typically learn to recommend from the conversational context itself. Generative recommenders, in contrast, learn a direct mapping from interaction history to item identifiers, capturing preference signals accumulated from users' past actions. When item identifiers are tokens in a language model's vocabulary, recommending an item and generating a response become the same operation, so conversational ability can be added without architectural change. However, this shared output space also means that both behaviors are carried by the same parameters: training the model to converse may overwrite the history-to-item mapping it has already acquired~. Its design is grounded in a single principle: conversation acts as a control layer over a generative recommender instead of recommendation signals. Recommendation therefore remains in the history-to-item mapping acquired from interaction sequences, while dialogue governs that mapping is invoked and its output is presented and revised. Our contributions are threefold. First, we expose recommendation as a learned decoding action, where a routing token decides when to recommend and re-emits the user history right before item generation. Second, we combine behavioral replay with instruction-data rehearsal to preserve recommendation accuracy during conversational adaptation. On Amazon Beauty and Toys~, INTEGER is competitive with both end-to-end CRS and modular pipelines and significantly outperforms the generative recommender it is adapted from. Third, our analyses show how conversational and behavioral training erode each other and how re-anchoring and rehearsal counteract this, and that refinement learns a single intent-agnostic replacement. Existing work approaches this task in three main ways. Conversational recommender systems learn recommendation directly from multi-turn dialogue, jointly modeling preference elicitation, item recommendation, and response generation~. Other work treats conversation as an additional feedback channel for an existing recommender, converting it into pseudo-interactions for sequential recommendation~ or into preference signals~. A third line adopts a modular design, in which an LLM handles the interaction and delegates recommendation to an external model or tool~. Conventional sequential recommenders~ assign each item a unique ID and score items through a large embedding table. Generative recommendation instead represents each item as a sequence of discrete tokens and generates the next item by autoregressive decoding~. Existing work has focused on semantic ID design~, training and decoding algorithms~, and multimodal item representations~. In all of these settings, recommendation is one-shot: the model produces an item from a fixed interaction history, and the user cannot revise its input except through further interactions.
