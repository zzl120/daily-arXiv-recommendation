This paradigm supports reasoning-intensive tasks whose answers are not contained in any single document but must be assembled from evidence distributed across multiple documents~. Given the limited interaction budgets of deep search agents, a central challenge in Web search is enabling these agents to surface the most relevant evidence effectively and efficiently. To provide deep search agents with relevant corpus evidence, prior work has explored several directions. Some approaches improve first-stage retrieval by training dense retrievers for agent-generated sub-queries~ or adapting lexical retrieval to long documents~. Another approach warm-starts the agent by decomposing the question and reranking results from complementary searches to construct an initial evidence context to guide iterative search and reasoning~. Retrieval-aware agent control has also been explored to mitigate reasoning stagnation and reduce redundant searches by monitoring information coverage and search novelty~. However, these approaches focus on retrieval, initialization, or trajectory control rather than reranking evidence throughout the search process. Reranking first-stage retrieval candidates is a common approach to improving retrieval effectiveness, typically using cross-encoders~ or LLM-based rerankers that assess relevance through prompting or reasoning~. Recent studies have extended reranking to deep search agents~, demonstrating improvements in retrieval effectiveness and answer accuracy. Within a deep search agent, however, reranking is not a one-time operation but is often invoked at every search call along the trajectory, adding latency without substantially reducing the number of searches. Moreover, existing approaches typically rank candidates solely based on agent-generated sub-queries, overlooking the original question's global information need, and rely on initial document tokens that may omit relevant evidence. Consequently, they improve retrieval effectiveness at the expense of efficiency, without substantially reducing the agent's search effort. Emerging System One models offer a promising direction for jointly improving retrieval effectiveness and efficiency. Unlike generative LLMs, these models produce structured, calibrated decisions in a single forward pass, enabling fast and cost-efficient inference~. Recent work by demonstrates that Jev, a System One model, achieves relevance judgments comparable to frontier models at substantially lower latency and cost. These capabilities are particularly valuable for deep search agents, where retrieval and reranking occur repeatedly. By prioritizing relevant evidence at each search step, System One reranking can expose agents to more useful information, potentially reducing search calls, agent reasoning overhead, and cost. However, adapting these models to deep search requires addressing long documents and the interplay between the global information need of the original question and the local information need of agent-generated sub-queries. To this end, the is to investigate how lightweight, repeated System One reranking improves the effectiveness and efficiency of deep search agents. Specifically, we address three research questions . How can System One models be adapted as in-loop rerankers in the context of deep search agents to improve retrieval effectiveness? How does System One reranking affect the agent's downstream answer accuracy and evidence recall? What is its impact on overall agent efficiency in terms of latency and cost? To investigate these questions, we introduce SOARS , a training-free framework that integrates System One reranking into deep search agents. SOARS represents long documents using query-relevant passages and reranks candidates in a single call, considering both the original question and the agent-generated sub-query. We evaluate SOARS on two deep search benchmarks, BrowseComp-Plus~ and WebShaper~, across six LLMs of varying families and sizes. Our results show that SOARS achieves retrieval effectiveness comparable to strong LLM-based rerankers while operating one to two orders of magnitude faster. At the agent level, SOARS prioritizes relevant evidence for subsequent reasoning, improving answer accuracy and reducing search calls across all backbones . A search action issues a sub-query $q_t$ to a retriever, which returns the list $L_{q_t}$ of documents retrieved for $q_t$. The agent operates under a limited interaction budget, so the order in which retrieved evidence is presented, and the form in which each document is exposed, determine what the agent ever reads and reasons over. Reranking $L_{q_t}$ can reshape this evidence, but since it is repeated at every search call along the trajectory, it must be not only effective but also efficient to be practical. This work introduces SOARS, a training-free reranker that reranks the candidates returned by every in-loop search before they reach the agent. The agent interacts with the corpus through issuing searches, previewing the returned results, and reading documents in full~. The agent then previews and reads from $L_{q_t}$ to gather evidence for $Q$. Because the agent inspects only the top of this list, the documents placed near its top determine what evidence enters the trajectory. Our objective is to rerank $L_{q_t}$ at each search efficiently in a way that the agent is exposed to more relevant documents. SOARS reranks the top $k$ documents of $L_{q_t}$ by preparing a query and a compact representation for each document and scoring them with a System One model. This would let more candidates fit within the model's context, so a large pool is reranked in a single call. Since an agent-generated sub-query $q_t$ captures a local information need, matching it alone may overlook constraints in the original question $Q$. We assess how integrating System One reranking into deep search agents affects end-to-end answer accuracy and evidence recall across two benchmarks. SOARS significantly improves answer accuracy across all LLMs, with relative gains ranging from 10.2\ These findings suggest that SOARS improves answer accuracy by promoting already-retrieved evidence into the documents agents preview, read, and cite. Furthermore, the average number of documents read increases significantly across all LLMs. As agents preview short document excerpts before selectively opening promising ones for full-text reading, this suggests that SOARS helps identify more useful evidence for deeper inspection. Notably, these gains are accompanied by fewer search calls , suggesting that better evidence prioritization reduces the need for additional retrieval. The same pattern generalizes to WebShaper, where previewed and behavior recall increase significantly for every backbone, with significant accuracy improvements for most. The number of documents read also increases significantly across all backbones, suggesting more promising evidence is selected for deeper inspection. These findings confirm that SOARS consistently improves evidence utilization throughout the search trajectory, contributing to higher answer accuracy. We evaluate the efficiency of per-step System One reranking across three dimensions, namely the number of search calls, per-query latency, and cost. We report results on BrowseComp-Plus, with broadly similar trends observed on WebShaper. SOARS reduces search calls across all LLMs , especially for search-intensive agents, from 23 to 14 for GPT-5.4 Mini and 32 to 21 for Haiku 4.5. By promoting relevant documents to the top of the ranked list, SOARS helps agents identify and utilize useful evidence earlier in the search trajectory, reducing the need for subsequent searches. Despite adding a reranking call per search, SOARS reduces per-query latency for nearly all backbones , from 113 to 84 seconds for GPT-5.4 Mini and 100 to 73 seconds for Opus 4.7. Fewer search calls offset the reranker's modest overhead, yielding a net latency reduction. These findings demonstrate that lightweight reranking can accelerate the overall search process by reducing the time spent on repeated search interactions. Total cost decreases for five of six backbones , particularly for expensive agents, from \$247 to \$119 for Opus 4.7 and \$194 to \$122 for Haiku 4.5. Reduced search effort offsets the minimal reranking cost, lowering overall agent compute. GPT-5.5 is the sole exception, with a modest cost increase potentially due to reading more evidence, contributing to higher accuracy . We introduced SOARS, a training-free framework that adapts a System One model as a reranker inside the deep search agent's iterative loop. Across six LLM backbones on BrowseComp-Plus and WebShaper, SOARS consistently improves answer accuracy and evidence recall while reducing the agent's search calls, latency, and cost.
