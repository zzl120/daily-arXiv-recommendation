Traditional retrieval matches queries against indexed item representations~. Generative retrieval learns to predict candidate identifiers directly, allowing semantic knowledge in the model to guide candidate selection~. Semantic IDs represent items as short token sequences whose prefixes group related items~. This structure lets a generator select candidates through successive token predictions. Existing methods address this cost in several ways: distillation teaches a smaller decoder or lightweight prediction heads to imitate a large teacher, reducing computation per prediction~; parallel prediction produces SID tokens in the same model call instead of waiting for each preceding token, reducing sequential computation~; speculative decoding lets a small model draft candidate sequences for batched verification by a large model~; prompt caching reuses attention states for shared input blocks, such as history and item representations, reducing repeated context processing~. These approaches lower the cost of online prediction, while candidate SIDs are still generated for each search. Repeated queries offer another source of savings: sharing large-model planning across users. We ask whether part of this planning can be performed offline and reused by users who submit the same query. The upper half of Figure~ makes the opportunity concrete: two histories lead to different complete SIDs, yet their shared initial tokens are recomputed for both searches. Our idea is to cache query-dependent SID prefixes and let the current history guide their completion online. Each prefix preserves a subtree with multiple continuations, so the online model can generate candidates beyond a precomputed list of complete SIDs. This would share expensive planning while keeping final candidate selection responsive to the user. Our click-log analysis examines the feasibility of this idea and the choice of prefix length. When predicting the next SID token at matched preceding prefixes, query information contributes much more at the first two layers than at later layers . This supports sharing coarse candidate structure across users. The suitable sharing boundary also varies by query: model-generated prefix sets at query-specific depths retain \ SIDs on average, versus \ two-token depth under the same prefix-count limit. These are reachable target fractions before online completion. A deeper cut saves decoding steps but narrows the available subtrees; a shallower cut leaves more choices for history-conditioned generation. The design must therefore identify reusable prefixes and select how far each query can reuse them. We implement this design as . In the lower half of Figure~, query $q_A$ reuses one token and $q_B$ reuses three; users searching for either query share its prefixes while their histories guide different suffixes. ReuseCut predicts these depths from query text using historical target-coverage labels. A 7B offline planner produces the shared prefix sets, and a 0.5B online model completes them using the current query and history. To guide the small model's suffix scoring with large-model knowledge, we apply path-level knowledge distillation from the 7B teacher. After scoring, branches are merged to form the final retrieval results, so branch selection affects which relevant SIDs enter the top-100 ranking. We develop BudgetCut to learn this selection under a fixed branch budget. On-policy distillation initializes its policy from marginal recall gains, and group-relative policy optimization refines the policy using the recall of complete selected branch sets.
