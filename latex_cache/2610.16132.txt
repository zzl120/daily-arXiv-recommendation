Stages optimize inconsistent objectives, upstream errors propagate irreversibly downstream, and system maintenance is costly. Generative recommendation has rapidly emerged as an end-to-end alternative : conditioned on the user profile and behavior history, an autoregressive decoder directly generates the identifier of the target item. TIGER first replaced random integer IDs with hierarchical semantic IDs obtained from RQ-VAE , placing semantically similar items close in code space; since then OneRec , OneRanker , RankGR , UniRec , and UniSGR have pushed this paradigm toward industrial scale. Yet semantic-ID generative recommendation and discriminative models differ in a structural way that has not been directly addressed: UniRec shows that the two are mathematically equivalent, and that the gap arises : structured attributes are folded into discrete codes after semantic-ID quantization. More fundamental is the : the target item is still being generated, so its true features cannot be retrieved; although the completed semantic ID can be mapped back to an item to retrieve its features, the generation probability at every level has already been determined and cannot be corrected retrospectively. We call this structural state during decoding the , which leads to two parallel consequences. Every semantic-ID codeword is predicted without target-item attribute information. At each level, generation is conditioned only on the user context and the already decoded prefix. The first level has no prefix at all and therefore has the highest conditional entropy and is most prone to error. Because semantic IDs are hierarchical, an error at any level is irreversibly propagated to all subsequent levels. Without an additional post-hoc feature-lookup pipeline, scoring degenerates into ranking based only on decoder hidden states. Retrieving features by mapping the completed SID back to an item can only repair ranking and cannot benefit the decoding process itself. In most end-to-end designs, the ranking head is built directly on top of the decoder and thus lacks the target-side feature crossing on which discriminative models rely. Most existing methods address only one of these consequences: some perform target-side interaction using candidate SID representations , some map decoded SIDs back to items for post-hoc reranking , and others adjust the generation policy through preference alignment ---yet the model remains unaware of the target attributes throughout decoding. The primary reason for regressing a continuous vector rather than autoregressively generating discrete attribute tokens as in CoA is inference efficiency. Industrial recommendation systems can involve many target-side attributes, including category hierarchies, brand, shop, price band, material, and more. If each attribute is generated as a separate discrete token, the number of decoding steps grows linearly with the number of attributes, and latency would far exceed millisecond-level online serving SLAs. TacGR compresses all target-side attributes into a single continuous vector \ }\), formed by concatenating multiple attribute embeddings, and requires only one prediction per semantic-ID level. Its inference cost is therefore decoupled from the number of target-side attributes. The second reason is . A discrete token is a hard decision: once an incorrect category is selected, the subsequent decoding path changes irreversibly and the error cannot be recovered. A continuous vector acts as a soft condition. Prediction error appears as a moderate displacement in the vector space and therefore induces a smooth perturbation to downstream code distributions rather than a discontinuous jump. The third reason is . A discrete token is restricted to the finite set of values in an attribute vocabulary and can only express categorical decisions such as ``which category does this item belong to?'' A continuous vector retains the complete information of the learned embedding space and can express semantic gradients that cannot be discretized into a single label, such as lying between two category prototypes or belonging to a relatively high-end shop segment. The three contributions are not independent tricks that can be arbitrarily combined. They form three links in a single chain of reasoning. The first innovation establishes the central claim: send a predicted continuous signal into the decoding path and use it jointly for generation and ranking. Once this claim is adopted, two questions immediately arise. First, because the target being approximated is itself learnable, does that target actually encode meaningful information? The second innovation, the anchoring auxiliary tower, answers this question by imposing a task-aligned semantic lower bound on the regression target and avoiding the trivial solution in Proposition 1. Second, because the injected signal is noisy, can it contaminate the main backbone? One component ensures that the target contains useful information; the other prevents the signal from leaking into paths where it should not propagate. Without the former, the module can look perfect on the loss curve while contributing nothing to business metrics. The denoising module is embedded in the memory encoder, as shown in Figure 2, and is governed by two design constraints. The dataset contains 2.42 billion samples, covering 6.46 million users and 7.53 million items. We compare against TIGER , OneRec-V1 , OneRec-V2 , UniRec , and UniSGR as generative recommendation baselines. UniRec is the most direct comparison to our method; we reproduce its attribute-chain mechanism on the same backbone to eliminate backbone differences. UniSGR is included as a unified generation-and-ranking framework for a more direct comparison of ranking performance. On the retrieval side, we report HitRate@100 and HitRate@500 for click and pay objectives. On the ranking side, we report AUC and GAUC for click and pay. TacGR uses an 8-layer decoder with an attention dimension of 512, grouped-query attention , and SwiGLU-MoE with 64 experts and top-2 routing. Both the embedding dimension and the side-information dimension are 128.
