Recent efforts to scale recommendation models have focused largely on increasing sequence-handling capacity: consuming longer histories, allocating more model computation to them, and engineering the serving stack to sustain the resulting workload~. When additional computation is placed on the online serving path, however, its cost scales directly with online prediction demand. Recommendation scaling is therefore not only a question of predictive gain, but also of where computation is placed and how often it must be executed. This raises two more fundamental questions that are easily obscured by generic compute scaling: Answering these questions leads naturally to a model--infrastructure co-design problem. The first is a question: the architecture must expose the computational components whose capacities can be scaled along different axes. The second is an question: those components should execute at their designated amortization scope and trigger, rather than all at request time. These two design problems are coupled through the model’s compute–state decomposition. The same computational decomposition that exposes distinct scaling axes also defines the state boundaries across which computation can be amortized, recomputed, and disaggregated. We develop , a sequence-transduction framework that instantiates this model--infrastructure co-design principle. Its model architecture exposes three distinct computational roles: A causal encoder transforms the evolving behavioral trajectory independently of the current candidate, allowing computation over overlapping prefixes to be amortized across prediction events. A bounded global--local memory separates the amount of history processed from the behavioral representation exposed to downstream prediction, making memory resolution an explicit scaling axis while exposing the memory as a reusable state boundary. Candidate queries cross-attend to the shared memory as part of the task-specific prediction path. Behavior memory KV is shared across candidate fanout while preserving candidate-specific fusion. This decomposition makes the amortization boundary explicit: behavioral-state construction over shared prefixes and its incremental refresh are amortized across requests and candidate fanout, while only prediction-conditioned computation scales with request and candidate demand. The infrastructure preserves and exploits the same decomposition in execution, translating the model design into substantial system-level efficiency gains. During training, variable-length behavioral prefixes from each trajectory share one causal encoding, while candidate fanout at each prefix shares one event state. During serving, bulk and nearline workers construct and refresh behavioral states on model rollout and behavior updates, while online workers consume bounded, immutable behavior memory KV cache for candidate-conditioned prediction. Thus, history-dependent computation is performed primarily when behavioral state is initialized or refreshed, while the online serving path is concentrated on state access and request- and candidate-conditioned prediction. This decomposition also lets us study how different compute allocations advance the recommendation-quality frontier. Our scaling experiments reveal unequal marginal returns across these scaling axes: encoder scaling improves prediction at fixed behavior-memory resolution but saturates beyond moderate depth at fixed fusion capacity; increasing supervision shifts the allocation frontier toward candidate-conditioned fusion; and the memory resolution needed to preserve quality remains roughly stable even as overall model capacity grows. Together, these results suggest that efficient scaling is a compute-allocation problem: additional capacity should be allocated according to component-wise marginal returns rather than increased proportionally across all computational roles. The disaggregated infrastructure preserves the benefit of this allocation in execution by amortizing history-dependent computation outside the online serving path, relaxing the coupling between history-side model capacity and online serving cost. Finally, we reuse the same behavioral memory interface for capability specialization across recommendation tasks. We first train the TransX backbone on response prediction, then post-train capability-specific memory readers and output heads for retrieval, preference ranking, and generative recommendation. Core training learns a reusable behavioral memory interface; post-training specializes how each capability queries it and maps it to task-specific outputs. The contributions of this work are: We formulate recommendation as repeated request-level queries over an evolving behavior stream, and expose a compute--state decomposition into sequence encoding, behavior memory, and candidate-conditioned fusion. This decomposition identifies the model states that can be shared across serving events and candidate fanout. The same compute--state decomposition defines the reuse and recomputation boundaries preserved by multi-prefix sequence-to-sequence training, sequence--fanout parallelism, tiered KV residency, and disaggregated serving. Expensive sequence computation can therefore be amortized across overlapping prefixes and executed outside the request path until behavioral state changes. Controlled experiments vary behavioral-encoder compute, behavior-memory resolution, and candidate-conditioned fusion compute, revealing unequal marginal returns across these scaling axes: encoder returns saturate beyond moderate depth at fixed fusion capacity, increasing supervision shifts the validation-selected allocation toward candidate-conditioned fusion, and the memory resolution needed to preserve quality remains roughly stable as model capacity grows. We post-train capability-specific memory readers and output heads for retrieval, preference ranking, and generative recommendation while preserving the behavior memory interface. We evaluate TransX as an industrial recommendation system rather than as an isolated model benchmark. The evaluation therefore considers predictive quality together with the training and serving properties that motivate the architecture: reuse of behavioral computation across serving events, candidate-fanout efficiency, online latency and freshness, and operational robustness under heterogeneous production traffic. Unless otherwise stated, we compare against the baseline production recommendation stack under matched data and product constraints. We deploy TransX in a large-scale social recommendation application with long, heterogeneous user histories and highly variable candidate fanout, ranging from approximately $0.5$K to $1.2$K candidates per request. The system serves on the order of $20$K requests per second and processes hundreds of millions of user interactions per day under strict latency and infrastructure-cost constraints. Online model scoring runs primarily on an H200 GPU serving fleet and is subject to a p99 end-to-end scoring-latency SLO of less than $50$ ms. Historical behavior is constructed over a 180-day lookback window, allowing the behavior encoder to exploit substantially longer context than the short-history features typically exposed to conventional ranking models. As described in Section~, a fallback DLRM~ is co-deployed to serve requests for which no valid KV cache can be retrieved. The deployed system follows the same disaggregated serving design. Bulk and nearline workers maintain behavioral state and publish compact behavior memory KV snapshots, while online workers perform only candidate-conditioned readout and prediction. This separation makes both model quality and infrastructure efficiency first-class deployment criteria. Models are retrained and freshly deployed daily, with an end-to-end refresh SLO requiring training, bulk prefill, and production rollout to complete within $20$ hours. Nearline state maintenance is subject to a p90 freshness-lag SLO of $2$ seconds, aligned with the system's typical pagination interval. For each TransX ramp, the control is the incumbent model currently serving the same recommendation product surface, so the reported gains measure the production transition rather than a comparison against an offline or simplified baseline. For the click/conversion prediction task on the primary landing and home-page surfaces, the control is the production HSTU-style~ sequential recommender, trained over a 180-day behavioral lookback window using our production configuration. This control performs history encoding and candidate scoring entirely on the online serving path. For retrieval, the control is a sequential embedding-based retrieval model whose user tower encodes up to 180 days of behavioral history with Transformer blocks. The user and item towers map into a shared 128-dimensional embedding space, and the resulting representations are used by an ANN service to retrieve the top-200 candidates, which are merged with candidates from other retrieval sources before downstream ranking. For the slate-ranking task used on notification and email surfaces, the control is a production DLRM-based learning-to-rank model in which behavioral history is represented through engineered aggregate and sequence-derived features and scored entirely online. Accordingly, the emphasis of this technical report is the production transition from established serving systems to TransX---including quality, efficiency, and operational behavior---rather than leaderboard-style benchmarking against generic reference models. A useful approximation to the latency-critical serving path is \[ T_{} T_{} + ( T_{}, T_{} ) + T_{} + T_{}, \] where $T_{}$ is snapshot lookup/admission and transfer, $T_{}$ is request/candidate feature preparation, and $T_{}$ and $T_{}$ are the candidate-conditioned model costs. At admission, each request resolves and pins one compatible behavior-memory snapshot for all candidate batches. A device-resident snapshot removes behavior-memory transfer from the latency-critical path; concurrent misses for the same snapshot are coalesced, and the resolved state remains pinned for the request lifetime. Request-side sparse features follow the same readiness discipline: GPU- and host-resident rows are served locally, while remote misses are deduplicated and batched by owning shard. We therefore quantize behavior memory KV before publication. The deployed codec uses a calibrated orthogonal rotation followed by energy-aware precision allocation under a fixed storage budget. These results motivate viewing recommendation scaling as . Behavioral encoding, memory budget, and candidate-conditioned interaction are distinct resources with different costs and returns. The preferred allocation therefore depends on the joint data--model operating point rather than on a fixed allocation ratio between encoder and fusion capacity. Operationally, this is particularly favorable for TransX: model capability can increase without requiring the persistent KV state transferred, cached, and consumed by online prediction to grow proportionally. TransX is organized around two coupled questions: where should additional model capacity be allocated to improve recommendation quality, and must increasing that capacity proportionally increase online serving cost? The model's compute--state decomposition separates sequence encoding, behavior memory, and candidate-conditioned fusion into distinct scaling axes, while the infrastructure preserves the same boundaries in training and serving. Behavior computation is shared across overlapping prefixes, recomputed as behavioral state changes, and materialized behind a bounded behavior-memory interface, while request-time computation is concentrated on candidate-conditioned prediction. Within the evaluated regimes, marginal returns differ substantially across these scaling axes. Encoder scaling improves prediction at fixed behavior-memory resolution but saturates beyond moderate depth at fixed fusion capacity; increasing supervision shifts the allocation frontier toward candidate-conditioned fusion; and the memory resolution needed to preserve quality remains roughly stable as overall model capacity grows. Together with disaggregated serving, these results suggest that efficient recommendation scaling is a joint problem of compute allocation and amortized/disaggregated execution: additional capacity should be allocated according to its marginal return rather than increased proportionally across all computational roles, while reusable computation should remain off the request-critical path. The same behavior-memory interface also supports capability specialization. Starting from a core response-prediction backbone, we post-train capability-specific memory readers and output heads for retrieval and preference ranking, with generative recommendation explored offline. Production deployment of the core, retrieval, and ranking variants further validates the framework across recommendation quality, training efficiency, and serving economics. The observed scaling patterns are empirical and conditional on the studied data, supervision regimes, architecture family, and deployment envelope; they do not constitute a universal scaling law or uniquely identify the mechanisms behind the patterns. Materialized behavioral encoder continuation and memory state maintenance also introduce freshness, storage, compatibility, and recovery costs. Finally, for task specialization via post-training, a shared behavior-memory interface and frozen backbone need not be optimal for every task. Future work should therefore study: adaptive allocation across encoder capacity, behavior-memory resolution, and candidate-conditioned fusion; and when the behavioral memory interface and model backbone should remain shared, be partially adapted, or become task-specific.
