Candidate generation can use separately encoded user or query and item representations with a simple similarity scorer~. This decomposition permits item representations to be precomputed and searched efficiently at catalogue scale~. By contrast, ranking operates on the smaller candidate set and can afford candidate-specific , which jointly processes each shortlisted candidate with the user's history and request features~, although real-time serving still constrains the computation performed for each candidate. Target-aware encoders use this per-candidate budget to distinguish a user's concurrent interests. Consider a shopper whose recent activity alternates between running gear and photography equipment. When scoring running shoes, the model should emphasise the sports interactions, and when scoring a camera lens, the photography interactions. A candidate-independent vector represents both interests jointly and may not identify which events support each candidate. Target- models such as the ~ ~ reuse one history summary for every candidate. Target-aware models such as the ~ ~, ~ ~, ~ ~, and ~ ~ instead condition part of their computation on each candidate. Target-aware Transformers such as the ~ jointly encode each candidate with the history, so their encoder must be evaluated separately for each candidate~. DIN instead evaluates a ~ for every pair. Target-aware operators must scale efficiently as histories and candidate sets grow. Candidate conditioning determines which history events matter for each target, but it does not remove a second modelling requirement: target-aware ranking must preserve target identity and user--target compatibility as distinct signals. A target's carries target-only information such as base-rate appeal and within-target feature interactions, whereas its to the relevant history represents user--target compatibility. For example, a holiday decoration may become broadly appealing during Christmas because the scorer can combine its target-only identity with calendar context, without requiring a matching seasonal pattern in the shopper's history. Compatibility is a different relation: a drill may score highly for a shopper whose recent activity includes paint, fixtures, and tools because it matches that renovation history. DIN can supply the target separately to its scorer, but its weighted pooling combines target-conditioned history content and compatibility in one vector. We instead decouple these roles: a similarity branch computes an explicit user--target interaction feature, an identity branch processes the target alone, and the scorer combines both signals with any contextual features.
