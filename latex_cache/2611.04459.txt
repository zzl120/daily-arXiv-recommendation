A trial succeeds when its ending is correct (a book meeting every predicate on a satisfiable task, an abstention on an NVR task) and the protocol checks hold. Volunteer and mixed tasks separate satisfying stated requirements from deciding to elicit them (one broad question suffices), following needs revealed over a conversation . Hidden tasks are a stress test. Real users sometimes state a requirement only after seeing a suggestion; that is critiquing , which we leave to later work. The hidden user never states it, so the agent must propose books before committing and search using verdicts that give no values or reasons. Wikidata does not record which formats a book comes in, so each book gets a simulated but fixed set , drawn from a hash of its Wikidata ID. In families the user accepts only one format, and at least one otherwise valid book in the 5k catalog lacks it. In families the user has a reading history that holds one valid answer and, for each hidden predicate, a book that fails only that predicate, so no single book in it gives a hidden value away. In the of these with two hidden predicates, the history as a whole hints at them, but agents do no better on the such tasks in the , the random 51 of the 150 families that every agent runs . Personas are synthetic, and only LLM users voice them. Besides meeting the predicates, a trial must pass five protocol checks: the agent recommends at most one book, never one from the reading history, checks its formats once the user names one, abstains on NVR tasks, and calls on the others. We ask four research questions: how much success is lost as requirements move from volunteered to askable or hidden, with the request held fixed? how does a schema-aligned search interface change end-to-end success over top-20 keyword search? how does success change with catalog size when every 5k answer is retained? which effects persist across models, trials, and users? The agents run on three open-weight models -- DeepSeek V4.1 Flash, GLM 5.3 Flash, and Qwen 3.8 27B, at temperature 0 -- and the frontier model GPT-6.1 Sol at its required default temperature, all with high reasoning effort. Every agent gets the same system prompt , which says that recommending a book that misses any requirement fails, and so does abstaining when the catalog has an answer. Both interfaces offer metadata, format-availability, and reading-history tools and the terminal , which scores the identifier passed, never a title parsed from text. The interface sums per-field Okapi BM25 scores and returns the top 20 without paging; the year field is not indexed, so year ranges are inexpressible. The interface offers case-insensitive conjunctive filters on genre, language, country (a parent label covers its children), year range, and acceptable formats, returning pages of 20 by Wikidata sitelink count or recency; an unknown value returns the valid vocabulary. The structured tool's prompt line lists these fields and the keyword line does not, so the contrast compares two bundles of tool and prompt over the same metadata, not retrievers alone. By default the user is rule-based: it holds the task facts and answers by fixed rules , using keyword matching to tell which fields each agent turn asks about. We checked the matching against an LLM's labels on held-out agent turns: precision , recall , and recall on generic requests such as ``Anything else?''. In the LLM-user block, GLM 5.3 Flash and Qwen 3.8 27B play the user instead, at temperature~1: they get the same rules, facts, and reveal tags but decide what to disclose and word their own replies, while verdicts still come from the identifier check. The base prompt tells agents to use rejections to pick a better candidate, but not that a rejection means a requirement failed or that a declined question hides one. A trial allows 20 agent turns, including turns that draw no verdict, and 600\,s of agent time, and also ends at a context overflow or after ten calls past a budget of 150 tool calls in one turn; agents are not told these caps.
