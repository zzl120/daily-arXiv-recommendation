Widening the beam adds latency to both decode and resolution, since each additional beam is another prefix to resolve, but not memory: GPU memory stays flat across beam widths, the serving counterpart of Figure~ , because cascade attention holds the history once however wide the beam. {fig0-overview} Retrieval is the first stage of an industrial recommender: from a corpus of order $10^{9}$ items, it selects the candidates a downstream ranker will score, under a tight latency budget. The dominant approach is two-tower retrieval with approximate nearest neighbor search~: user and item towers embed both sides in a shared space and retrieval returns the items nearest the user vector, so the two interact only through a final dot product. Since sequential recommenders scale like language models~, generative retrieval instead generates the next item as a language model generates the next token~. A GR model can represent items in one of two forms. , such as PinRec~, reads and predicts one dense embedding per item, so a fixed context covers a long history, but it still retrieves through an ANN index. , introduced by TIGER~, quantizes each item into a semantic ID of $L$ discrete codes and generates it with beam search, so the output space can be decoded directly into items and steered during generation. As a result, no ANN index sits on the request path, and a new item is retrievable as soon as it has an SID. Its inputs are costly, however, since every history item takes $L$ tokens, even though history matters: Recall grows by $10\ $1{,}024$ to $6{,}144$ tokens . We ask whether one model can have both, reading history at one token per item while keeping SID outputs, their supervision, and the diversity their output space allows. Three obstacles stand in the way . The first is that input and supervision pull in opposite directions. In a causal model, every token the model is trained on is also input for every later token. SID tokens give rich supervision, one label per code, but cost $L$ input tokens per item, and compressing them removes the token-level supervision. Naive fixes pick one side: a separate dense encoder and SID decoder loses direct attention to distant history and gets one label per forward pass, while merging each item's SIDs into one token keeps the input short but trains on one label per item instead of $L$. The second is beam decoding cost. A KV cache avoids recomputing the history~, but every beam still attends over all of it, so cost grows with beam width, and some beams lead to no matching item. The third is diversity. Because beam scores accumulate over levels, the beams collapse onto a few prefixes ($11.9$ distinct level-$1$ codes among $100$ beams; Table~), and temperature sampling, the usual remedy, lowers spread further and produces more SIDs that do not exist in the corpus. Prior work leaves these obstacles open. On input and supervision, every prior design pays on one side. Deployed SID retrievers keep multi-token SIDs in the input and pay at serving~, as do methods that restructure SIDs to cut decoding steps~; COBRA~ and GPR~ add a dense token or a second decoder on top and pay even more. SPARC~ and ACERec~ take the other side: they merge each item's SIDs into one input token, so they train on one label per item instead of $L$. On serving cost, speculative decoding~ and serving co-design~ accelerate GR but keep full-model wide-beam decoding, and shared-prefix attention~ has not been applied to SID beam search. On diversity, no GR work diversifies beam search, so the usual knob remains temperature. Finally, embedding GR and SID GR have never been compared head to head online; the only direct comparison, LIGER~, is offline. We address all three with PinGER (Pinterest GEnerative Recommender; Figure~), which interleaves the two item forms in one causal backbone: in training, each history item contributes its $L$ SID tokens followed by one dense token, and every SID token is a prediction target. An asymmetric attention mask lets SID tokens read the dense history and the shallower codes of their own item, while dense tokens read only earlier dense tokens. No later position ever reads a past SID token, so serving drops them and reads the history at one dense token per item, computing exactly the same function . In training, sparsity-aware attention kernels compute only the entries the mask permits, so a history costs less attention than in TIGER while supplying the same supervision . The model is thus trained with the full SID supervision of TIGER and served at the input cost of embedding GR. For diversity, a hierarchical prefix penalty selects beams one at a time, charging each candidate by the depth of the prefix it shares with beams already chosen . For serving, cascade attention reads the shared history once per request rather than once per beam, constrained decoding keeps every beam on an SID that exists, and a host-local index resolves SIDs to items without a network call . Offline, it matches TIGER's Recall@100 while serving $6 $ fewer tokens, and at equal serving tokens it exceeds TIGER by $9.5\ embedding retriever, PinRec, by $3.9 $ . An encoder--decoder would place the two in separate backbones, but its decoder then sees the history only through cross-attention and receives one next-item label per forward pass. We therefore keep both representations within a single causal backbone, with the following designs. During training the user sequence is represented by dense embeddings and SID tokens interleaved. Each history item $i$ contributes $L{+}1$ consecutive tokens ): its SID tokens $s^{1}_{i}, ,s^{L}_{i}$, embedded by the per-level codebooks, followed by one dense token $e_{i}$. All $L{+}1$ tokens share the position index $i$, so the positional encoding counts items rather than tokens. Attention is restricted by a single predicate, stated as three rules ). A dense query $e_{i}$ attends only to dense keys $e_{j}$ with $j i$, never to an SID token. The level-$ $ SID token of item $i$ attends to $s^{1}_{i}, ,s^{ }_{i}$ and to every $e_{j}$ with $j<i$. An SID token never attends to another item's SID tokens, nor to the dense token of its own item. Rule~3's second half is a causality constraint imported from serving: at decode time the next item's own embedding is precisely the unknown, so a training-time path from $s^{ }_{i}$ to $e_{i}$ would be unreproducible at inference. Rules~1 and~3 together mean that no position outside item $i$ ever attends to item $i$'s SID tokens. Those tokens can therefore be dropped from the sequence without altering any dense hidden state, and hence without altering the distribution over the next identifier. So training runs at $L{+}1$ tokens per item and serving at one, over the same context and computing the same function of the history: at decode time only the dense tokens are kept, and the sole SID tokens present are those of the beam being extended ). The pretraining objective of the sequence model is SID cross-entropy, applied per level with logits weight-tied to the corresponding RQ-VAE codebook and uniform weights across levels. Every SID token is a prediction target; dense positions carry a reserved level identifier and are never targets, so the model is never asked to regress an embedding. A sequence of $S$ tokens, or $|H|=S/ $ items, therefore yields $|H|\,L$ next-token predictions per forward pass, where an encoder--decoder supervises only the codes of a single target item. Each prediction is conditioned on the dense history and the true shallower codes of its own item, so level $ $ is trained given $H$ and $c_{1}, ,c_{ -1}$, the same condition under which beam search generates it at inference. The asymmetric mask makes serving cheap, but training still runs at $L{+}1$ tokens per item, and at long contexts attention dominates the step time. Most of this attention is masked. In Figure~ , the unmasked entries are the dense-token columns, which every later token reads, and a small triangle per item for its SID tokens. Off-the-shelf sparse attention cannot exploit this structure. FlexAttention~ skips a block only if it is fully masked. Every block below the diagonal contains part of a dense column, so no block is skipped and the cost equals that of full causal attention. We instead wrote custom forward and backward kernels for this mask. Each query tile contains whole items, so all of its rows attend to the same earlier dense tokens. The kernel gathers these tokens and computes their attention without a mask. It then computes attention among the tile's own tokens, where each SID token reads the shallower codes of its own item; this is the only part that needs the mask. Online softmax~ combines the two. The backward pass splits the work by key: dense keys reduce to causal attention over the dense tokens, and each SID key is read only by tokens of its own item. Compared with TIGER, the attention cost is lower by a factor of about $L^{2}/ $ despite the extra token per item . At serving, the mask reduces to standard causal attention, so these kernels are not needed. We further drop the level-$L$ SID token from the training input, since the dense token that follows it is never a prediction target and no later token attends to it. This keeps every target and shortens the sequence to $L$ tokens per item. Together, the two changes raise training throughput by $94\ context length. Conditioning controls what kind of item is generated, and the diversity penalty spreads the beam across items of that kind. {fig3-cascade} The beam score accumulates over levels, so at each level the ranking is dominated by the prefixes already chosen. The $W$ best continuations of one strong prefix usually outscore the best continuation of any other, and top-$W$ selection keeps the beam inside a few subtrees. Because prefixes are semantic , the retained beams are also similar in content: at $W{=}100$ they span only $11.9$ distinct level-$1$ codes . Temperature sampling does not recover the lost spread: both spread and lookup@$L$ degrade monotonically in $T$ . Sampling perturbs selection but not scoring, so beams admitted on improbable codes are outscored at the next level and their slots return to the dominant subtrees. The final level has no later level to prune a poor draw, so that is where temperature hallucinates and validity collapses: the generated identifiers name no corpus item. Section~ evaluates the trade-off between spread and recall. The pretrained model of Equation~ is trained with a next-token loss on engaged items only, which has two problems. First, it has no contrastive loss to push the model away from negatives. Second, it is teacher-forced on individual codes, with no item-level objective that matches autoregressive decoding at inference. As a result, what the model retrieves is poorly aligned with what the ranker scores highly. We therefore post-train with DPO~. Preference pairs are sampled from the serving logs, where every impression is stored with the utility the production ranker computed at request time. Within each slate we sort items by this utility and pair the top three against the bottom three. TIGER~ introduced generative retrieval for recommendation: items are quantized into hierarchical SIDs with an RQ-VAE, and a sequence model generates the next item's SID with beam search. The paradigm has been deployed at YouTube~, Kuaishou~ and Snapchat~; all keep multi-token SIDs on both the input and the output side, paying $L$ tokens of context per history item and $L$ decoding levels per request. Restructuring the SIDs, with a single-level codebook~, parallel generation~ or order-agnostic sets~, cuts decoding steps but leaves SIDs as the input representation. Embedding GR such as PinRec~ instead reads and predicts one dense embedding per item and retrieves by nearest-neighbor search, which puts an index on the request path. Hybrids pick one side of the trade-off: COBRA~ interleaves SIDs with a dense vector and preserves SID supervision, but pays the extra positions at serving too; SPARC~ and ACERec~ merge each item's SIDs into one input token and train on one label per item; GPR~ splits intent and SID generation across two large decoders. We keep COBRA's interleaving in training only, and serve on the dense tokens alone . Embedding GR and SID GR have been compared offline by LIGER~ and argued over~, but never head to head in production; we report that comparison. Wide-beam SID decoding is the serving bottleneck, and prior work attacks it from two sides. Speculative decoding with draft models or heads~ and serving co-design~ accelerate generative recommenders but keep every beam attending over the full history. Paged KV caches~ and shared-prefix attention~ share the stored history across beams, yet still read it once per beam; we fold the beam into the query dimension so the history is read once per request . Decoding must also stay on SIDs the corpus contains: we adopt the vectorized trie of STATIC~ to constrain each level, and resolve SIDs to items from a host-local index . In language generation, diverse beam search penalizes beams that choose the same token at the same step~, a flat penalty with no notion of hierarchy. SIDs are hierarchical, so we charge each candidate by the depth of the prefix it shares with beams already chosen . We know of no generative retrieval work that diversifies beam search; the usual knob is temperature, which we show lowers both spread and validity.
