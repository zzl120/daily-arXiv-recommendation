Retrieval-augmented generation , for example, relies on vector search to retrieve relevant information from external document collections and utilizes the retrieved information to provide large language models with additional context~. In vector search, data objects and queries are encoded as high-dimensional vectors, and the objects are ranked according to their distances or similarities to the query. Vector search commonly uses either dense or sparse representations. Dense vectors effectively capture semantic similarity but may not preserve exact lexical information such as rare terms or identifiers~. Sparse vectors retain term-level information and are therefore well suited to exact lexical matching~. By combining the complementary semantic and lexical signals from dense and sparse representations, hybrid retrieval can achieve higher retrieval effectiveness than dense-only or sparse-only retrieval~. Hybrid dense-sparse vector retrieval has also seen growing adoption in practical information retrieval systems~. In hybrid dense-sparse vector retrieval, each item $x$ in the base dataset is represented by a dense vector $x^d$ and a sparse vector $x^s$. Given a query $q$ with its dense representation $q^d$ and sparse representation $q^s$, the hybrid distance $D_h $ is defined as a weighted sum of the dense distance $D_d $ and the sparse distance $D_s $: D_h = D_d + D_s , where $ $ controls the trade-off between semantic and lexical matching. This weight is naturally query-dependent. A conceptual question may rely more on dense similarity, while a query containing rare terms or identifiers may require stronger sparse matching. In this work, we consider the setting where $ $ is specified at query time, focusing on efficiently supporting retrieval under the resulting query-specific hybrid distance. A common existing approach to hybrid retrieval is a two-route pipeline that searches dense and sparse indexes independently, merges their candidate sets, and reranks them under the query-specific hybrid distance~. This design entails an effectiveness--efficiency trade-off: for a requested result size , retrieving fewer candidates from each index risks missing some of the final hybrid top-$k$ results, whereas retrieving more candidates increases the costs of both searches and reranking. Alternatively, a graph constructed directly under a certain $D_h$ is tailored to the hybrid query weight used during construction and cannot maintain stable retrieval performance under dynamically varying query weights~. Our key observation is that Although they emphasize different aspects of relevance, both are derived from the same content and therefore induce correlated similarity structures: objects with high dense similarity also tend to have high sparse similarity. Figure~ illustrates this observation. A more direct and efficient design is to use a unified index in which dense and sparse signals are combined during graph construction and traversal. With this observation, we propose the , a graph-based index for dense-sparse hybrid retrieval with dynamic query-specific weights. UniGraph constructs a single bounded-degree graph by merging neighborhoods sampled at multiple $ $ values for various dense-sparse trade-offs. The resulting graph retains edges useful across different dense-sparse trade-offs, allowing the same graph to support different query weights without reconstruction. At query time, our search algorithm first obtains a set of entry points according to the query-specific $ $, aligning graph initialization with the query's dense-sparse preference. It then traverses the unified graph and ranks results using the query-specific hybrid distance. To further improve search efficiency, we develop a dense-first hybrid distance pruning strategy during traversal, which computes the dense component first and utilizes sparse vector norms to determine whether exact sparse distance evaluation can be skipped. We develop an $ $-adaptive search strategy in UniGraph. It routes each query through a sparse-guided or dense-guided execution path according to trade-off value $ $ and applies dense-first hybrid distance pruning to avoid unnecessary exact sparse distance computations. For a query $q$, a dense vector index retrieves top candidates ranked by the dense distance $D_d$, while a sparse vector index retrieves top candidates ranked by the sparse distance $D_s$. The number of candidates retrieved from each index can be adjusted to balance recall and retrieval efficiency. Retrieving more candidates can improve recall but increases search and reranking costs, whereas retrieving fewer candidates reduces these costs but risks missing hybrid top-$k$ results~. Another approach is to construct a proximity graph using the hybrid distance with a fixed weight $ $, such as $ =0.5$~. Because nearest-neighbor relationships can change with the hybrid weight, a graph constructed at a fixed $ $ may lack connections between items that are close under other query weights. When the query weight differs from the weight used for graph construction, the search may need to explore more vertices to reach the nearest neighbors. This can increase query cost or reduce recall for a fixed search budget. Although this approach can be improved by first performing coarse retrieval with a dense or sparse index and then conducting fine-grained search on the hybrid graph~, it still fundamentally relies on a graph constructed with a fixed hybrid weight and therefore cannot adapt to query-dependent hybrid weights. Fusion-based systems typically retrieve dense and sparse candidates separately and then combine their truncated result lists. Weighted score fusion~ preserves score magnitudes but requires calibration, whereas reciprocal rank fusion ~ avoids calibration but discards score magnitudes and is sensitive to its rank constant. They both can lose candidates before fusion. Dense vector ANNS methods include locality-sensitive hashing~, quantization and inverted file methods , and graph-based indexes . Empirical evaluations show that graph-based methods offer competitive recall-efficiency trade-offs and often perform particularly well in high-recall regimes~. Efficient sparse retrieval is commonly implemented with inverted indexes. Representative approaches accelerate retrieval through pruning or compact index structures. Classical block-max pruning and BMP skip low-potential document blocks~; Seismic groups inverted lists into geometrically cohesive blocks~; Sinnamon uses compact sketches~; and SINDI uses optimized inverted lists for approximate sparse maximum inner-product search~. A graph-based ANNS method for dense-sparse hybrid vectors~ aligns the dense and sparse distance distributions and refines an HNSW-style topology under a predetermined hybrid weight. Its fixed-weight topology may not match queries with different weights. Existing query-dependent hybrid methods face limitations in dense-sparse retrieval. IVF-MIPS~ reuses IVF partitions for query-side reweighting, but lacks cross-weight neighborhood optimization. LADR~ seeds dense graph exploration with lexical results, but is tailored for dense retrieval. While GPU-based Allan-Poe~ supports dynamic multi-path weighting without index reconstruction, UniGraph builds a CPU-based bounded-degree graph by merging multi-weight sampled neighborhoods. Other multi-metric approaches and DEG~ support query-specific weights via Pareto frontier neighborhoods or multi-graph traversals~. However, DEG is restricted to fixed-length Euclidean embeddings; its formulation and analysis do not cover high-dimensional inner-product sparse vectors, making it inapplicable to our dense-sparse hybrid setting without fundamental redesign. Dense and sparse vectors are paired representations of the same items in the base dataset. They are partially correlated: not identical, but not independent. This partial correlation creates both the problem and the opportunity. The problem is that two-route retrieval may miss hybrid top-$k$ results when an item does not rank highly in either vector modality. The opportunity is that neighborhoods under nearby $ $ values overlap, allowing a unified graph to reuse edges across multiple hybrid weights. The effectiveness of discrete sampling depends on how the hybrid neighborhood changes with $ $. For a fixed center base vector pair $x_i$ and a candidate neighbor $x_j$, the hybrid distance can be rewritten as { D_h =D_s + -D_s ). } This equation shows that the hybrid distance between two base vector pairs changes linearly with $ $. For a fixed center base vector pair $x_i$, each of the remaining $N-1$ base vector pairs defines a linear hybrid distance function of $ $. When two candidates are compared, their relative order can change only at a crossing of their distance functions. Only crossings within $ $ can affect the candidate ranking, and the partial correlation between dense and sparse distances further limits the number of such crossings. Many candidate pairs have the same relative order under both the dense and sparse distances. For such pairs, this order is preserved under any convex combination of the two distances. Even among the remaining crossings, those within the selected neighbors or within the unselected candidates change only their internal order. For a per-weight neighbor-set size , the neighbor set changes only when a candidate crosses the top-$k_g$ boundary. Computing the sparse inner-product distance is especially costly because it requires matching query terms with irregularly stored nonzero entries. Existing systems commonly search separate dense and sparse vector indexes and rerank the union of their candidates, incurring two retrieval passes and potentially discarding items that rank highly only after the semantic and lexical signals are combined. Constructing a graph-based index directly under a hybrid distance can mitigate this premature candidate loss. However, because varying the hybrid weight alters the underlying neighborhood relationships, a single static graph built at a fixed weight cannot accommodate dynamic query-specific weights. Therefore, we propose a Unified Hybrid Graph , which merges neighbor sets computed at multiple hybrid weights into a single bounded-degree hybrid graph, enabling hybrid vector retrieval with different query-specific weights without index reconstruction. We further develop an adaptive weight-guided search framework that chooses between sparse- and dense-guided entry points according to the query weight, together with a dense-first hybrid distance pruning strategy that avoids unnecessary exact sparse distance computations. Extensive experiments show that UniGraph provides a favorable Recall-QPS trade-off across different query weights.
