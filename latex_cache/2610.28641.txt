We release the benchmark generation and evaluation code. dense retrieval tabular foundation models retrieval-augmented generation financial transaction data embedding model evaluation Retrieval-augmented generation systems are increasingly built over structured, tabular enterprise data such as financial transaction logs, where the standard practice is to linearize or aggregate rows into text and embed the result with a general-purpose sentence encoder. An alternative, recently popularized by domain-specific or foundation models, is to represent structured rows directly with an encoder pretrained on transaction sequences, avoiding a potentially lossy text-conversion step. This raises a practical question for anyone building a RAG system over financial data: We answer this empirically using NVIDIA's Transaction Foundation Model ~, a 29M-parameter decoder pretrained on transaction sequences, evaluated against five text embedding baselines on a retrieval-augmented question-answering benchmark we construct over IBM's synthetic AML transactions dataset~. Dense passage retrieval~ and retrieval-augmented generation~ are now standard components of knowledge-intensive NLP pipelines. General-purpose sentence embedding models such as BGE~, E5~, and GTE~ are commonly used as retrievers in such pipelines, including over data that originates in structured or tabular form. Financial-domain adaptations of encoder-only models, such as FinBERT~, were built for sentiment classification rather than retrieval, and are typically repurposed for embedding via mean-pooling. Separately, tabular and transaction foundation models such as TabFormer~ and NVIDIA's Transaction Foundation Model~ learn representations directly from structured transaction sequences. To our knowledge, prior RAG evaluation benchmarks for structured financial data rely on human-curated question sets; our benchmark instead guarantees ground-truth correctness by computing every answer directly from the source data via deterministic aggregation. We use the split of IBM's synthetic Anti-Money-Laundering transactions dataset~: 5{,}078{,}345 transactions across 515{,}088 unique accounts and 30{,}470 banks, with a 0.10\ laundering rate. We generate a retrieval corpus of 161 entity-level documents (one text summary per unique account, bank, currency, payment format, date, sender- receiver pair, or the whole dataset) and 1{,}026 question--answer pairs from 35 templates across seven categories, sampling up to 40 entities per template. Every answer is computed directly via pandas aggregation over the raw transaction rows, guaranteeing ground truth without relying on an LLM. Every QA item additionally carries a field linking it to the supporting corpus document , which decouples retrieval evaluation from generation evaluation. For end-to-end evaluation, the top-$k$ retrieved documents are concatenated as context and passed, together with the question, to a single shared local LLM (Llama 3.2 1B via Ollama, temperature 0, JSON-constrained single-value output), held constant across retrievers so only the retrieved context varies. Generated answers are graded with exact/tolerant rule-based matching (numeric answers within a relative tolerance, ISO dates, and categorical substring match), with an optional secondary-model judge pass restricted to rule-based misses, using a model distinct from the generator to avoid self-grading leniency bias. All 1{,}026 QA pairs are evaluated; the retrieval corpus is never subsampled, so every retriever always searches the full 161-document pool. The overall picture is that the value of a transaction-native foundation model over generic text embeddings is : it earns its keep specifically for individual-entity, high-cardinality behavioral queries, while a well-engineered generic-embedding pipeline over aggregated summary text is a strong, considerably cheaper substitute for coarse-grained categorical lookups. Our benchmark is built on a single synthetic dataset and domain (AML transactions); questions are generated from 35 fixed templates and so lack the linguistic variety of real user queries; end-to-end accuracy is measured with a single, small generation model; results are reported from a single seed without confidence intervals, which matters most for the smallest categories ; and among the fair baselines, has roughly three times TFM's parameter count, so it is not a size-matched comparison. We introduced a deterministic RAG evaluation benchmark over financial transaction data and used it to show that a domain-specific transaction foundation model outperforms size-matched generic text embedding models overall, but that this advantage is concentrated in individual-entity queries and disappears or reverses for low-cardinality categorical queries, where a well-engineered generic-embedding pipeline is competitive or better.
