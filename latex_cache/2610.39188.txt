These results show that separating addressable evidence from propagated state makes reading more and reasoning deeper independently controllable and jointly useful. } } {Long-sequence recommendation, Recommender systems} Sequential recommendation models can typically be improved in two ways: More events expose more evidence about a user's interests; more layers let a model reinterpret that evidence as its representation of a candidate evolves. We call these directions and . A useful architecture for long-sequence recommendation should control them independently and benefit from both: reading more history should not enlarge the state that every layer transforms, and adding layers should not cut off access to the original history. Yet current designs couple these axes. Sequence encoders keep event representations active across layers ; lengthening history therefore expands work throughout the stack. Target-aware pooling and retrieval-based rankers bound active state by summarizing evidence before feature interaction, but this makes evidence selection effectively one-shot. Once an event is omitted, later layers cannot recover it. This matters because the useful evidence can change during reasoning: an early representation may match a candidate to a stable preference, while a later one emphasizes the current session. Existing designs thus face a structural choice: carry more evidence through every layer, or let deeper reasoning operate on evidence chosen only once. We introduce the , which separates what the model can read from what it must carry. Typed history, request/user context, and matched events remain in persistent external banks. Candidate features initialize a fixed-size workspace that alone moves through the stack. Evidence scaling increases bank cardinality and read length, whereas reasoning scaling increases the number of workspace layers. These are separate structural controls: changing either does not enlarge the representation governed by the other. This separation is useful only if later layers can use the retained evidence differently. Each LWR layer therefore its workspace, uses the result to each bank, the returned evidence, and the responses with ranking features . Non-final layers write a few tokens to an archive. Because both the workspace and archive evolve, a later layer can formulate a candidate-specific follow-up read from earlier results while still accessing the original evidence. Longer histories provide more addressable evidence; deeper stacks ask better-informed questions of it. {lwr_architecture.png} The central test is whether the separated axes produce useful gains rather than merely configurable knobs. We evaluate four architectures on a grid of history lengths and reasoning depths, then read that grid in three ways. The evidence curve holds depth fixed and asks whether longer history helps. The reasoning curve holds history fixed and asks whether added reasoning continues to pay off relative to its training compute. The joint curve removes both restrictions: among all history--depth combinations, it traces the configurations that are not beaten in both compute and NE. It therefore asks how well each architecture allocates a compute budget between reading more and reasoning deeper, rather than forcing both axes to increase in lockstep.
