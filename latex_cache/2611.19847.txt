Instead of assuming that every user should receive the same amount of LLM reflection, we argue that reflection has user-dependent value and should be spent where it is most likely to change the learned recommender mixture. We propose , a budgeted reflection-allocation framework that estimates reflection value from recommender-side self-doubt before making training-time LLM calls. By gating cross-tool disagreement with ranking fragility, preserves the base agent's recommender tools, prompts, and inference reranking while selectively reducing repeated reflection. Our analysis explains why low-margin users provide greater rank-flip opportunity and why disagreement should be treated as a conditional signal rather than an unconditional objective. These results suggest that scalable recommendation agents require not only stronger reflection modules, but also principled policies for deciding when reflection is worth using. Directly optimizing is unacceptable before making LLM calls, so the central challenge is to build a cheap pre-reflection surrogate for the value of reflection. LLM-based recommendation has moved from semantic scoring toward reasoning over user histories, item text, and ranking evidence. Early approaches formulate recommendation as point-wise preference prediction, prompt-based scoring, or zero-shot reranking~. They exploit textual knowledge but often operate on restricted candidate sets and remain weakly coupled with full-catalog collaborative signals. A second line aligns collaborative representations with language-model spaces, enabling LLMs to consume user/item embeddings or generate recommendation outputs~. More recent work further emphasizes preference reasoning beyond shallow semantic matching; for example, ThinkRec uses reasoning activation and personalized expert fusion to improve LLM-based recommendation~. Together, these studies show that LLMs can enrich recommendation with semantic and reasoning ability, but they also expose a deployment tension: direct LLM recommenders must generate valid item identifiers, rerank limited candidates, or pay substantial inference and training costs. takes a complementary route. It keeps full-catalog scoring inside conventional recommenders and uses the LLM only for agentic reflection and final reranking. The key question therefore shifts from making the LLM recommend directly to deciding when its costly reflection is worth invoking during agent training. Language agents often extend LLMs beyond pure text generation by connecting them to external knowledge sources, symbolic modules, APIs, or specialist models~. This line is commonly described as LLM tool use, but the ``tools'' in that literature range from search engines and calculators to code interpreters and domain models. Representative systems interleave reasoning and action~, learn module invocation from self-supervised demonstrations~, improve API calling with retrieval-aware training~, and optimize module-use trajectories through contrastive or trajectory-level reasoning~. These works establish external-module access as a way to mitigate missing knowledge, limited exact computation, and unreliable direct generation. Recommendation agents instantiate this paradigm where output validity and catalog scale are central. Rather than asking an LLM to generate item identifiers, module-based recommendation agents use conventional recommenders to produce valid full-catalog rankings and let the LLM reason over recommender evidence. ToolRec studies LLM-empowered selection among recommender modules~, AgentDR uses LLM agents for dynamic recommendation~, and PRTA learns personalized tool-mixture memories through local recommender evaluation, recommender comparison, and ranking comparison~. studies a complementary dimension: given the same reflection operation, which users should receive LLM feedback under a budget? This separates the reflector from the allocator and treats user-level reflection as a selective training decision. is also related to cost-aware reasoning and selective computation. LLM routing and cascade methods invoke expensive reasoning only when cheaper models or intermediate states are insufficient~. Adaptive computation, early exiting, and selective prediction similarly allocate computation or coverage according to confidence~. Their shared principle is that expensive computation should follow expected value rather than a uniform schedule. Reflection allocation differs from model routing or abstention because the decision is not which model answers a query, but whether an LLM should update a user's personalized tool-mixture memory during training. Its value is measured by downstream top-$K$ ranking after the memory update, making recommender-side evidence especially useful before any LLM call is made. This connects to active learning: uncertainty sampling and margin selection prioritize examples near decision boundaries~, while query-by-committee uses disagreement as an informativeness signal~. In recommendation agents, however, disagreement can indicate either complementary evidence or uniformly weak recommenders, so gates disagreement by ranking fragility instead of treating it as an unconditional objective. Large language models have become an appealing interface for recommender systems because they can reason over user histories, item text, and intermediate ranking evidence~. Yet direct LLM recommendation is still poorly matched to full-ranking scenarios: LLMs may hallucinate non-existent item IDs, struggle with large catalogs, and incur substantial latency when asked to reason over many candidates~. A recent line of work therefore casts the LLM as an agent that orchestrates conventional recommenders as external modules~, echoing the broader shift from passive generation to language agents that call external modules and APIs~. In this setting, recommender tools provide valid full-catalog rankings, and the LLM reasons over their exposed evidence. This architecture raises a question that classical recommendation rarely needs to ask: Existing recommendation agents mainly study prompts, memories, and recommender-tool interfaces, and typically apply reflection to every sampled user once reflection is deemed useful. The policy is simple, but the value of reflection is not uniform. Recent LLM routing and cascade studies make a similar point at the system level: expensive LLM computation should be invoked selectively when cost and quality must be balanced~. In recommendation agents, some users have sharp and mutually consistent recommender-tool rankings, so the mixture over recommenders is nearly determined before LLM feedback. Others have flat score margins or conflicting recommender evidence, where a small change in personalized tool-mixture memory can move relevant items near the top of the list. The distinction matters because LLM judgments are useful but noisy: unnecessary updates can consume calls and perturb reliable mixture memories, especially when LLM evaluators exhibit order or self-evaluation biases~. We study reflection allocation as a first-class problem for recommender agents. The goal is to separate two roles that are often entangled. The defines how LLM feedback changes a user's tool-mixture memory, following the broader literature on language-agent reflection and self-feedback~; the decides which users should receive that feedback. Before invoking the LLM, estimates which users are likely to benefit from reflection and allocates the limited budget to those users. The estimator is gated: margin-based ranking fragility is the primary signal, while cross-tool disagreement is admitted only when the current ranking is sufficiently fragile. This requires no additional model training and no extra LLM calls. is not a new recommender backbone or reflection prompt; it decides when the existing reflection operation should be spent. The recommender tools still rank the whole catalog, and inference-time reranking remains unchanged, isolating the paper's central claim that reflection should be allocated rather than automatically spent. The design also clarifies a common intuition about uncertainty. Cross-tool disagreement sounds like a natural reason to reflect: if recommender tools disagree, the LLM should decide which recommender to trust. This intuition is related to classic query-by-committee active learning, where committee disagreement identifies informative examples~. In recommendation agents, however, disagreement is not always value. It may indicate a recoverable conflict where one recommender exposes the relevant neighborhood, or it may indicate that all recommenders are locally unreliable. In the latter case, reflection spends calls reallocating weight among weak alternatives. We evaluate on full-ranking recommendation benchmarks. Across datasets and reflection budgets, preserves the accuracy benefits of uniform reflection while using fewer LLM calls, and its strongest budget setting improves top-ranked quality over a full-reflection agent baseline. A controlled branch comparison further shows that the allocation score is correlated with realized user-level reflection gain, rather than only improving aggregate metrics after the fact. We also find that disagreement is useful only when conditioned on ranking fragility. The broader message is that recommendation agents should optimize not only they reflect, but also reflection is warranted and which uncertainty signals should control that decision.
