In an agentic assistant, a generation layer consumes retrieval output first, and that assumption breaks in three ways. The agent reads the results before the user does . The user’s action can come several turns or sessions after retrieval . Outcomes blend retrieved content with the model’s own knowledge . We call this the attribution gap. In an agentic AI assistant, search becomes a subagent whose output is consumed by a generation layer before the user sees anything. Each assumption fails, and each failure is a structural shift rather than a tuning problem. In gallery search, a user types “birthday invitation,” scans 40 templates, and clicks one; the click grades retrieval. In an assistant, the user asks for a birthday invitation, the search subagent retrieves templates, and the agent picks one and builds the design. The user never sees the other 39. There may be no click at all, and whatever the user does see has already been filtered and reordered by the agent. In a conversation, the same asset can be retrieved in turn 1 and again in turn 3, then exported in turn 5 or in a different session. Without an identifier that links the action to a specific retrieval event, timing cannot say which retrieval earned it. A bad outcome cannot be split between retrieval failure and generation failure, and a good outcome can hide a retrieval failure the model quietly compensated for. Without per-component instrumentation, teams rely on session-level proxies such as retry, abandonment, and task completion. Retry alone fails in both directions. It fires on generation failures unrelated to retrieval, and stays silent when the model covers for a retrieval failure. We call this the attribution gap. Prior work frames agentic retrieval , reintroduces fine-grained feedback into generative search , and documents technical debt in production ML and drift in agentic systems , but leaves retrieval attribution in production unresolved. Four fields close the gap. retrieval\_id is a unique identifier on every retrieval event. returned\_asset\_ids is the full ranked list at fire time, before the generation layer filters or reorders it; alone it enables Layer 1 and is the highest-value single change. consumed\_asset\_id is the asset on every action event, whether a user action or an agent tool call. source\_retrieval\_id is the retrieval\_id that supplied that asset, on the same action event; for an asset already placed in the document, it is inherited from the placement event. All four are logging additions, not predictive models; no new modeling is required. Because source\_retrieval\_id names a retrieval rather than a session, it resolves cross-turn recurrence and survives session boundaries, so exports landing in a new session stay attributable. Joined, the four fields recover the retrieval rank of the asset actually used, independent of display order, letting RAG evaluation frameworks such as RAGAs and ARES use direct attribution instead of timing heuristics. The retrieval role tag is written on the retrieval event alongside them. No shared standard yet covers production instrumentation of agentic retrieval, as TREC and TREC iKAT do for traditional and interactive IR. Deployments reporting LARA should disclose which lineage fields are implemented , how retrieval role is assigned, which actions count as user-initiated use, whether P95 latency and tokens per successful task are logged, and whether telemetry passed automated validation .
