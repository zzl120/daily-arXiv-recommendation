Modern recommender systems commonly use a retrieval--ranking cascade . Retrieval selects candidates from a large item collection , while ranking predicts user feedback using the retrieved candidates and additional contextual features. Both stages depend on the same user history, creating substantial opportunities for shared historical modeling . Recent unified architectures reuse history representations across tasks and recommendation stages through shared modeling, joint training, and cross-stage caching , yet retrieval and ranking operate with different information available within an interaction. Sharing history computation alone does not resolve the representational difference between retrieval and ranking. Retrieval makes a decision from the user history and the current request, whereas ranking operates after a candidate item has been introduced and can additionally use candidate-side context. Sequential models, however, commonly represent each interaction as an item- or event-level state . This leaves the information-availability boundaries within an interaction implicit. A unified retrieval--ranking model therefore benefits from representing the intermediate states through which an interaction evolves. {r}{0.48 } {image/Life.png} Figure~ illustrates the interaction lifecycle considered in this work. A Request is linked to an Item through retrieval; contextual information is then incorporated, and ranking predicts the resulting user Action. Following this progression, we propose the Lifecycle-aware Interaction Factorization Transformer . LIFT factorizes each interaction into four ordered states---Request, Item, Context, and Action---according to when information becomes available, and serializes them into a causal sequence. Retrieval reads the Request state, while ranking reads the Context state after the candidate and its contextual features have become available. The serialized lifecycle sequence also supports shared historical computation across recommendation stages. During online serving, the historical sequence is prefilled once and its cached states are reused by retrieval and ranking, which read the Request and Context states, respectively. We instantiate this representation with Role-Conditioned Attention, which shares Query and Key projections while conditioning Value and Output transformations on lifecycle roles. A lightweight Pre-LN Bias further conditions the feed-forward path on the current role. Retrieval and ranking retain their task-specific candidate processing, supervision, and prediction heads while sharing the causal history encoder. We compare LIFT with single-task models, multi-task models, and unified sequence models on ML-20M and Taobao. LIFT achieves the highest Joint Score among the evaluated joint models on both datasets. Sequential recommendation organizes user behavior as a temporally ordered interaction sequence to model behavioral order, evolving interests, and long-range dependencies . GRU4Rec encodes behavior sequences with recurrent neural networks, while SASRec introduces self-attention for sequential recommendation . Subsequent work extends Transformer-based sequence modeling through bidirectional representations, temporal intervals, and self-supervised objectives . HSTU further formulates recommendation as sequence transduction for large-scale, non-stationary behavior streams . LIFT represents the request as a distinct token, enabling the model to make explicit use of request-side information that is available at retrieval time. Prior work has explored different levels of integration between retrieval and ranking . CoRR jointly improves a retriever and a ranker through adaptive negative sampling and knowledge distillation . More recent work moves toward unified model architectures. UniGRF reformulates retrieval and ranking as generative objectives within a common framework . OneRec replaces the cascaded pipeline with a generative recommender and iterative preference alignment . OnePiece uses structured context for both retrieval and ranking, together with block-wise latent reasoning and progressive multi-task training . UniPinRec unifies the input format, model architecture, and training pipeline, and reuses user-history computation across stages through cross-stage KV caching . LIFT explores a different representation granularity by factorizing each interaction according to information availability. Existing sequential formulations typically associate an interaction or action event with a single sequence state, whereas LIFT exposes multiple causal states within the interaction itself. Their order follows when Request, Item, Context, and Action information becomes available, allowing retrieval and ranking to read distinct lifecycle states within the same causal history model. Multi-task learning coordinates parameter use across multiple prediction tasks through shared representations, gated experts, or a combination of shared and task-specific experts . Shared-bottom parameter sharing follows the classical multi-task learning paradigm . MMoE uses task-specific gating over shared experts , while PLE further organizes shared and task-specific experts . LIFT combines shared history encoding with stage-aligned state readouts: retrieval and ranking reuse the same causal interaction sequence while reading different states suited to their respective stages. In LIFT, the retrieval task generates candidate items based on the user history and the current request, while the ranking task predicts user feedback for candidate items. During training, both tasks share the same lifecycle sequence and historical encoding results, while differing in state readout positions, candidate processing, negative sampling, and supervision. During online serving, the ranking stage further introduces candidate-related features after the retrieval candidates have been determined. As illustrated in Figure~, a user interaction contains information with different semantics, including a request, an item, contextual features, and user feedback. Based on the semantics of these fields and their availability during the recommendation process, we represent the interaction of user $u$ at time $t$ as e_{u,t} = ( x^{R}_{u,t}, x^{I}_{u,t}, x^{C}_{u,t}, x^{A}_{u,t} ), where the four types of fields describe the trigger condition, interaction object, candidate context, and user response, respectively. This decomposition is determined by the generation dependencies and availability of the fields, independently of how the fields are organized in a particular data table. $x^{R}_{u,t}$ denotes the Request information, namely the request-side inputs available before the candidate items are determined. It includes the user identifier, current query or request features, session information, temporal features, and device- or traffic-related context, which together describe the conditions that trigger the interaction . $x^{I}_{u,t}$ denotes the Item information, namely the relatively stable attributes of the interacted item, including its identifier, category, brand, and content features. In large-scale retrieval systems, item-side representations are commonly precomputed or organized into retrieval structures for efficient candidate generation . $x^{C}_{u,t}$ denotes the Context information, namely the candidate-related features formed after the item is introduced into the current request and interaction scenario. Examples include time-windowed item statistics, user--item interaction statistics, candidate sources, and scene features determined before scoring . Statistics computed from historical behavior use only information available before the current time step. Such candidate-conditioned modeling is widely used in behavior-aware ranking models . $x^{A}_{u,t}$ denotes the Action information, namely the user feedback generated after item exposure or interaction, including clicks, dwell time, collections, purchases, and ratings . Historical interactions use the observed Action, while the ground-truth Action at the target position is excluded from the input and used only to construct the training supervision or evaluation label. Retrieval is performed before a candidate item is selected, so its representation should depend on the historical sequence and the current Request, but not on the Item, Context, or Action of the current interaction. The Request state therefore forms the retrieval readout. Ranking is applied after a candidate item has been introduced and its candidate-dependent features are available, while the user Action remains unknown. The Context state consequently forms the ranking readout. These two states are produced by the same causal sequence model but correspond to different information sets, allowing shared historical modeling without collapsing the stage boundary between retrieval and ranking. The resulting sequence preserves both cross-interaction historical dependencies and information availability within each interaction, providing retrieval and ranking with a shared input space and semantically distinct state readout positions. In practical recommendation logs, a single request event may contain multiple exposure samples corresponding to different candidate items . These candidates are generated under the same request and have no temporal precedence relation with each other. Directly applying a standard lower-triangular mask would therefore introduce an artificial ordering between co-occurring candidates. We extend the causal mask to preserve temporal causality across events while isolating different exposures within the same event.
