First and foremost, the signature feature of inverted indexes is that a sparse query vector only needs to touch the posting lists associated with its non-zero vector components. For sufficiently sparse vectors, this drastically reduces the search space. Standard graph-based indexes discard this structure. explicitly ports this structural advantage of the inverted index into graph search via a technique we call , which precomputes, for every vocabulary term, the documents with the largest weight on that term, and initializes the graph search from the documents listed under the query's highest-impact terms. Better entry point selection for graph search is a well-studied problem in the vector database literature, both for dense retrieval~ and by seeding graph traversal with the results of a separate lexical retrieval stage~. differs from prior work in using the sparse embeddings themselves as the entry point selection mechanism, which requires no additional retrieval system and almost no additional work at query time, making graph search $1.95-2.59 $ faster on its own in our experimental evaluations. Secondly, we further accelerate via an optimization we call that is also inspired by inverted index designs for LSR. Learned sparse embeddings exhibit ~: a small number of components carry most of each vector's weight. We exploit this property by sketching each document as its $R$ largest-magnitude components and running the graph traversal entirely on these sketches, then reranking the final candidates against the full vectors. Because learned sparse weights are non-negative, a sketched score is always a lower bound on the exact score, so only the navigation of the graph is approximate, and the returned results are scored exactly. This sketching is complementary to quantizing the stored weights, which we also apply; sketching reduces how many components each distance computation touches, while quantization reduces the cost of each one. Our final key optimization is not related to accelerating the query time of but rather the graph index construction. Traditionally, graph-based vector search indexes are constructed by calling the query function as a subroutine, inserting each new node by searching for its nearest neighbors among the documents already in the graph and adding edges according to a set of heuristics. As we show in this paper, sparse vectors are ill-suited to this search-based construction approach: while graphs over dense embeddings typically see diminishing returns beyond a construction beam width of roughly 200~, we observe that HNSW graphs over learned sparse embeddings require a beam width of 2000 to achieve competitive search quality . However, this increase blows up the graph construction time by roughly an order of magnitude, and on the MS MARCO v2 dataset, we estimate that we would require several days to build the graph. To solve this problem, we take inspiration from PiPNN~, a recently proposed index construction algorithm that replaces the incremental search-based procedure of prior systems with vector partitioning and hashing. PiPNN's partitioning step, which assigns points to randomly sampled leaders, closely mirrors the shallow $k$-means clustering that Seismic uses to organize its posting lists, and we find that it partitions learned sparse vectors effectively. However, we cannot apply PiPNN to learned sparse vectors out-of-the-box because PiPNN computes nearest neighbors within each partition using dense matrix multiplication, which is wasteful for sparse vectors spanning tens of thousands of dimensions. Again taking inspiration from inverted index designs for LSR, we instead compute these inner products from a small inverted index built over each partition. We apply this approach to develop a sparse variant of PiPNN we call , followed by a single refinement pass in which each document searches the finished graph from its own term seeds. This reduces the time to construct a graph from 5.5 hours to 47 minutes on the 8.8M MS MARCO v1 collection with SPLADE-CoCondenser embeddings. While we show that 's sparse PiPNN graph is somewhat weaker than an HNSW graph under standard search, the order-of-magnitude improvement in construction time allows us to build the graph for MS MARCO v2 in hours as opposed to days. In addition to improving our scientific understanding of index design for learned sparse retrieval, enabling graph-based indexes to be more efficient for sparse vector workloads also has important practical implications. Many modern retrieval systems now deploy so-called search strategies where dense and sparse retrieval are combined to produce a final list of results. Since such systems already typically deploy graph-based indexes for dense retrieval, they may be able to consolidate and simplify their infrastructure by reusing the same components for sparse search as opposed to having to maintain separate inverted index logic. Moreover, the popularity of graph-based indexes has led to a mature ecosystem of high-performance libraries and remains an active area of research. Thus, efficient graph-based search for LSR can enable the sparse retrieval community to also take advantage of these ongoing developments. In summary, this paper makes the following contributions: We challenge the conventional wisdom that graph-based indexes for sparse vector similarity search are uncompetitive with inverted indexes at practically relevant document collection sizes. We support this claim by presenting , a new system for graph-based learned sparse retrieval that achieves substantial performance improvements over standard graph-based search designed for dense retrieval via three algorithmic techniques which we highlight further below. These results call into question the default choice of inverted indexes for deploying learned sparse retrieval. We present a new approach for selecting entry points for graph-based similarity search tailored to the structure of learned sparse embeddings. In particular, we precompute a list of documents with the largest weights per vocabulary term and initialize graph search at the nodes associated with the query's highest-impact components. Inspired by the concentration of importance property of learned sparse embeddings, we propose a simple and effective sketching technique that retains a document embedding's $R$ largest-magnitude components and performs graph traversal entirely on the sketched vectors. We observe that this reduces query latency with negligible loss in search quality. We find that the traditional search-based iterative graph construction procedures used by popular indexes such as HNSW and DiskANN are especially poor fits for LSR because sparse embeddings require searching a much larger pool of candidates to build sufficiently navigable graphs. While applying traditional graph-based construction methods, in conjunction with our aforementioned optimizations, can produce competitive performance with inverted indexes, the build time is prohibitively expensive at scale. To remedy this bottleneck, we take inspiration from the recently proposed PiPNN construction algorithm~ and adapt PiPNN to the sparse setting by utilizing inverted indexes in the construction process. Sparse vector search is a foundational problem in information retrieval dating back to early foundational work on bag-of-words and term frequency representations of text~. However, traditional sparse lexical vectors are fundamentally limited in that they can only match queries to documents with exact keyword overlaps. sparse representations were conceived to address this shortcoming by utilizing neural networks to learn high-dimensional representations of vectors with a small number of nonzero components such that each component represents a generalized concept as opposed to a fixed word. Following the revolution in transformer-based representation learning, a number of works have studied how to train or fine tune learned sparse representations~. One of the most influential families of learned sparse embeddings models is SPLADE~ which established learned sparse retrieval as a state-of-the-art technique for first-stage text retrieval. Recently, introduced SPARSEUP, a next-generation learned sparse embedding model that achieves improved retrieval quality over SPLADE and, to our knowledge, currently constitutes the best-in-class sparse embedding model for first-stage retrieval. Furthermore, another very recent line of work has studied the notion of learned sparse embeddings which replace the query encoder model with a learned lookup table~. In addition to training models for encoding effective learned sparse embeddings, the retrieval community has also proposed numerous techniques for efficiently searching over these representations. A key finding in early work within this area is that learned sparse representations generate term distributions that differ considerably from the Zipfian nature of bag-of-words text representations, rendering traditional inverted indexes designed for text matching as inefficient~. Several of the early specialized indexes for learned sparse retrieval involved graph-based search. The Neurips 2023 Big ANN benchmarking competition~ included a dedicated learned sparse retrieval track where the winning solutions, PyANNS and GrassRMA, utilized graph-based vector search, a dominant approach for dense vector retrieval~, for learned sparse similarity search. Both PyANNS and GrassRMA utilize the HNSW graph index~ with additional low-level optimizations, such as integer quantization of values and graph reordering~, to improve performance. Notably, these methods do not seek to infuse the structural properties of inverted indexes into graph-based search, which, at a methodological level, differentiates . These graph-based methods subsequently lost their standing as the state-of-the-art indexing solution for LSR following the introduction of Seismic~ which achieved substantial efficiency improvements over PyANNS and GrassRMA using an inverted index tailored to the idiosyncrasies of learned sparse embeddings. Seismic has since been further improved in a number of follow-on works~. In addition to Seismic, several other systems have proposed efficient inverted indexes for LSR including Block-Max Pruning ~, Dynamic Superblock Pruning ~, and SINDI~ that each seek to accelerate the posting list traversal component of inverted index-based search. The latest version of Seismic, described in the work of ~, includes further performance optimizations that achieve significant search quality-efficiency improvements over both other inverted index designs for LSR and graph-based approaches and, to our knowledge, represents the current state-of-the-art system for LSR. We close this gap. Our core insight is that standard graph-based search begins every query from a fixed, query-independent entry point, and must then traverse the graph to converge to the neighborhood of the query's nearest neighbors, paying for distance computations at every hop along the way. An inverted index, in contrast, needs no such traversal: the query's non-zero components directly identify the posting lists where its answers are guaranteed to reside. Term-based entry point selection brings this advantage to graph search by initializing the search at nodes that carry large weight on the query's most important terms, which leads to fewer wasted distance computations. Specifically, in the offline phase, described in Algorithm~, we precompute for every vocabulary term $t V$ a seed list $H_t$ containing the $L$ documents with the largest weight on that term, that is, the $L$ documents $d$ maximizing $x_d $, along with the largest weight on the term, $w_t = _{d} x_d $. Each seed list is maintained as a min-heap of capacity $L$, so the lists can be built in a single pass over the non-zero entries of the collection in $O $ time. The resulting table holds at most $|V| L$ entries which concretely translates to roughly 8 MB of space on the MS MARCO v1 8.8M passage collection, a negligible space overhead in comparison to the 8.8 GB used to store the remainder of the index. The second core optimization at the heart of is approximate routing via sparse sketching, which is inspired by the concentration of importance phenomenon of learned sparse embeddings identified by . In essence, concentration of importance states that a small fraction of the non-zero components of learned sparse vectors, which themselves are a small proportion of the total number of dimensions, contains the majority of the $ _1$ mass of the vector. While utilize this insight in the design of Seismic, we leverage this same structure for faster graph-based traversal. To our knowledge, this is a novel optimization in the context of sparse graph ANN since prior graph-based systems for LSR such as PyANNS and GrassRMA adopt quantization techniques to represent the vectors in lower precision but do not consider dropping low-magnitude non-zero components entirely. In particular, our sparse sketching scheme, as described in Algorithm~, involves constructing, for every document $d$, a sketch $_d$ that retains only the $R$ largest-magnitude non-zero components of $x_d$ and sets the remaining components to zero. Importantly, sketching affects only search: the graph itself is constructed on the full vectors, as are the seed lists, so the edges of the graph reflect exact similarities between documents. We store these sketches as a second copy of the collection, quantized to 8 bits, and run the entire beam search over them: both the choice of which nodes to expand and the decision of when to terminate are made using the sketched scores $ q, _d $. Once the search terminates, we rescore every document in the final beam with its exact score $ q, x_d $ against the full vectors and return the top $k$. Because the weights of learned sparse embeddings are non-negative, the sketched score is always a lower bound on the exact score, $ q, _d q, x_d $, and the error is confined to the documents' smallest components. Thus, the sketch only perturbs the route the search takes through the graph, while the returned results are always ranked by their exact scores. Moreover, when $R$ is at least the number of non-zero components of every document, sketched search reduces to search over the full vectors. On MS MARCO v1, an HNSW graph built with an efc of 2000 is $1.7$--$3.5 $ faster to search than one built with an efc of 200 at recall@10 targets between 95\ To circumvent this prohibitively long index construction time, we turn to PiPNN~, a recent algorithmic breakthrough in efficiently constructing graph-based ANN indexes that completely avoids the iterative search-based insertion procedure. Unfortunately, we cannot use PiPNN directly out-of-the-box for LSR because several steps of the algorithm are specifically designed for dense vectors. As described in Algorithm~, we modify the original PiPNN construction procedure to be amenable to sparse vectors. The key insight behind our approach is to replace PiPNN's dense vector multiplication subroutines with sparse computations by utilizing inverted indexes to efficiently compute pairwise inner products. In particular, we apply this idea at the two stages of PiPNN that are dominated by dense computation. First, PiPNN partitions the collection by randomized ball carving: it samples a set of leaders, assigns every point to its nearest few leaders, and recurses until every partition holds at most $C$ points. Rather than comparing every point against every leader, we build an inverted index over the leaders' non-zero components, so each point accumulates scores only for the leaders with which it shares at least one term; a point that shares no term with any leader is assigned to a leader chosen by hashing, so that such points do not all collapse into the same partition. Second, within each leaf partition $P$, PiPNN computes all pairwise similarities with a dense matrix multiplication, at a cost of $O $, which is wasteful when vectors span tens of thousands of dimensions but have only around a hundred non-zero components each. We instead build a small inverted index over the documents in $P$ and accumulate every pairwise inner product by iterating over its posting lists, at a cost of $ _{t} |P_t|^2 / 2$, where $P_t$ denotes the documents in $P$ with a non-zero weight on term $t$. The remaining steps of PiPNN, HashPrune and RobustPrune, carry over directly, with similarities measured by inner product rather than Euclidean distance throughout. Finally, deviating from the original PiPNN algorithm, we add a final refinement pass in which each document searches the finished graph starting from its own term-based seeds and re-prunes its neighbor list with the results. Although this pass performs one search per document, it searches a completed graph rather than inserting documents one at a time, and we find that it is important for search quality at very high recall targets. With leaves of at most 1{,}024 documents and a maximum out-degree of 64, Sparse PiPNN builds the graph for the 8.8M-passage MS MARCO v1 collection in 47 minutes, compared to 5.5 hours for HNSW with an efc of 2000. Our core insight behind the design of GRIP is that we can infuse the strengths of inverted indexes into graph-based search. To that end, we introduced three optimizations that accelerate query processing and index construction, namely term-based entry point seeding, approximate routing via sparse sketching, and Sparse PiPNN, each of which is inspired by, or directly uses, inverted indexes. Together, these allow GRIP to outperform Seismic, a state-of-the-art inverted index, by 2.2–3.4× on the 138M-passage MS MARCO v2 collection with SPLADE-CoCondenser embeddings. These results challenge the recent consensus in the vector search community that inverted indexes are the better choice for learned sparse retrieval at realistic collection sizes. These gains do come at a cost: GRIP’s index is larger than Seismic’s and takes longer to build. Closing this gap, for instance through graph and vector compression, is an important direction for future work. Nevertheless, within LSR specifically, our results call into question the default choice of inverted indexes for deploying sparse retrieval, and may open the door to applying sparse embeddings in new, ambitious applications that demand more scalability. More broadly, we believe that our insights on combining the strengths of inverted indexes and graph-based indexes may have implications beyond learned sparse retrieval. Graph-based search for LSR was not inherently uncompetitive; it simply had not yet borrowed what made inverted indexes successful. We suspect the same is true in other data structures problems where one technique has been set aside in favor of another, and where the better answer may be to combine the strengths of both. Exploring the generality of our insights to other problems may also be a promising direction of future work.
